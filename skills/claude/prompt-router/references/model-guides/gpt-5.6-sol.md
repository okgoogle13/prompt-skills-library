# GPT-5.6 Sol

## Reasoning / Thinking
- Depth via `reasoning.effort`: `none | low | medium (Default) | high | xhigh | max`. Docs mapping: `none` = latency-critical with no reasoning benefit, `low` = efficient with a small latency overhead, `high` = "Hard reasoning, complex debugging, deep planning", `xhigh` = "Deep research, asynchronous workflows and agentic tasks", `max` = maximum depth for the most complex tasks.
- Additionally an **independent** switch `reasoning.mode`: `standard` (Default) and `pro` — "for difficult tasks that need more model work and can tolerate higher latency and token usage". Pro tokens are billed at the model's standard rates. Mode and effort are chosen separately.
- `reasoning.context` controls reasoning persistence across turns: `auto | current_turn | all_turns`. GPT-5.6 **defaults to `all_turns`** (earlier models to `current_turn`); `all_turns` renders compatible reasoning items from earlier turns. Summaries are opt-in via `reasoning.summary` (`auto` = most detailed level available); with `store: false`, reasoning items come back as `encrypted_content` and can be passed back in follow-up calls.

## Prompting Style
- **Lean prompting is the central rule:** remove repeated instructions and examples, state each instruction exactly once, expose only relevant tools, and keep tool descriptions "concise and precise" (including return fields, types, error behaviour). OpenAI measures roughly 10–15% better eval scores at 41–66% fewer tokens and 33–67% lower cost — explicitly labelled "directional".
- **Set autonomy and approval limits explicitly:** name safe local actions (read files, edit code, run tests), require confirmation for "external writes, destructive actions, purchases, or a material expansion of scope". Avoid repeated approval boilerplate; it creates unnecessary clarifying questions.
- **Control length in two stages:** default level of detail via `text.verbosity` (`low | medium | high`), task-specific requirements in the prompt. When asking for brevity, also say what must be kept (docs example: "Lead with the conclusion. Include the evidence needed to support it, any material caveat, and the next action").
- **Tone through concrete writing decisions** rather than adjective labels (avoid "friendly").
- **Programmatic Tool Calling (PTC)** for bounded workflows that filter/rank/aggregate many results. Do not use it when one call suffices, outputs are small, each result changes the next decision, or approvals are needed. Routing instructions name the tier, allowed tools, output schema and concurrency limits. Multi-agent orchestration is **beta** on the Responses API.

## Strengths & Weaknesses (prompt-relevant)
- Positioning: "GPT-5.6 flagship model for complex professional work" — top tier of the GPT-5.6 family (alongside Terra and Luna). OpenAI's current flagship group is GPT-6 (gpt-6-astra, gpt-6.1-sol, gpt-6-luna); GPT-5.6 Sol is under "More models", with no deprecation entry. Name caution: in GPT-6, "Sol" denotes the balanced middle tier ("Balanced speed, cost, and intelligence"), not the top tier — so the bare alias `sol` points to gpt-6.1-sol.
- Strengths: token efficiency ("flagship-level performance with fewer output tokens"); frontend/design work ("more polished and usable websites and applications", stronger layout and hierarchy judgements); intent inference (infers goal and desired depth of work from context better); agentic multi-turn work via persisted reasoning and PTC.
- Weaknesses/quirks: safeguards can block or refuse requests, occasionally also legitimate work (mainly security and biology); generation **pauses mid-stream for several seconds** while classifiers check synchronously — design timeouts and streaming accordingly. Pro mode is not for "routine, latency-sensitive, or high-volume work" and not without a measured quality gain. Not supported: Realtime, Assistants, fine-tuning, embeddings, image generation/image edit, video, audio (speech/transcription/translation) and moderation endpoints, legacy completions (hosted tools `image_generation`/`code_interpreter` are unaffected).

## Output & Format Conventions
- Context window **1,050,000** tokens, max. input **922,000**, max. output **128,000**; knowledge cutoff **16 Feb 2026**; input text + image, output text only.
- Endpoints: `v1/chat/completions`, `v1/responses`, `v1/batch`. Features: streaming, structured_outputs, function_calling, file_search, image_input, web_search, prompt_caching. Hosted tools include web_search, file_search, image_generation, code_interpreter, hosted_shell, apply_patch, skills, computer_use, mcp, tool_search. Control output length via `text.verbosity`.
- Prices per 1M tokens: input $4, cached input $0.4, output $20 (since 21 Aug 2026; per the model page a promotional price "at least through November 21, 2026"). Family rule: "Prompts with >272K input tokens are priced at 2x input and 1.5x output for the full request." Prompt caching: cache writes cost 1.25× the uncached input rate, reads stay discounted — track `cached_tokens` and `cache_write_tokens`, set explicit breakpoints.
- The alias `gpt-5.6` routes to GPT-5.6 Sol; only the one snapshot ID `gpt-5.6-sol` is listed (no dated snapshot).

## Migration Notes
- **AWAY FROM GPT-5.6 Sol**: map `reasoning.effort` onto the target model's effort ladder (names and levels differ per provider; only carry over `none`, `xhigh`, `max` if the target guide documents them); `reasoning.mode`, `reasoning.context` and `text.verbosity` fall away and must be rebuilt as prose instructions. Re-add explicit brevity/verbosity rules and any removed few-shot examples, since other models infer less from context. Remove PTC/multi-agent routing. Check the 1.05M-token context assumption — target models are usually much smaller. To gpt-6-astra: per OpenAI "generally better than GPT-5.6 Sol and earlier models at staying coherent during long tasks"; `none` effort is not supported there (→ `low`) — the same applies to gpt-6.1-sol, and for both, tool calling requires the Responses API.
- **TO GPT-5.6 Sol**: official successor for, among others, `gpt-5-2025-08-07` and `o3-2025-04-16` (shutdown 11 Dec 2026), and `o3-mini-2025-01-31` (shutdown 23 Oct 2026). (1) Keep the existing effort level as baseline and additionally test **one level lower**. (2) Slim the prompt: strip repetitions and examples carried over from the GPT-5 era; tighten tool descriptions. (3) Review blanket brevity instructions — GPT-5.6 is inherently more concise than GPT-5.5, and "Be concise" lines can make answers too short; replace them with `text.verbosity` plus task-specific length guidance. (4) Move reasoning, tool-calling and multi-turn workloads to the Responses API. (5) Leave `reasoning.context` at `auto`/`all_turns`; use `current_turn` only if earlier reasoning is irrelevant. (6) Add autonomy and approval limits explicitly, rather than relying on the model to pause on its own. (7) `reasoning.mode: "pro"` optional and independent of effort for quality-critical tasks. (8) Plan for refusal and stream-pause handling.
