# MiniMax-M3

## Reasoning / Thinking
- Type: **binary on/off** (hosted API) — `thinking: {"type": "adaptive"}` turns thinking on, `thinking: {"type": "disabled"}` turns it off. No effort ladder, no `budget_tokens`; thinking depth is controlled via prompt text, not a parameter. The MiniMax API now knows `output_config.effort` / `reasoning_effort` (low…max), but it is effective only for MiniMax-M3.1-Flash-Preview — M3 ignores the fields silently ("Other models ignore this field").
- The Hugging Face model card names three modes for `thinking`: `enabled` (reasoning always on), `adaptive` ("M3 automatically determines when additional reasoning is beneficial"), `disabled`. The hosted API documents only `adaptive`/`disabled`; `enabled` therefore concerns self-hosting with the open weights.
- **The default depends on the endpoint** — the most common migration trap. Anthropic-compatible Messages path: "`MiniMax-M3`: thinking is off when `thinking` is omitted". OpenAI-compatible Chat Completions path: "`MiniMax-M3`: adaptive thinking is on by default". So **always set it explicitly**, never rely on the inherited default.
- Vendor recommendation on which mode when: thinking on for complex reasoning, agentic tasks and long-running collaboration; thinking off for latency-critical cases such as conversation and code completion.
- **Interleaved thinking**: M3 thinks between tool rounds — before each tool use the model reflects on the environment and tool results before choosing the next action.
- Strict multi-turn rule: the **complete** assistant message must go back unchanged into the history ("preserve them unchanged in later turns, especially in tool-use conversations"). Anthropic path: complete `response.content` list (thinking/text/tool_use). OpenAI path: complete `response_message` incl. `tool_calls`, with `reasoning_split=true` additionally `reasoning_details`. With the native `<think>` format do not touch the `content` field. Anyone filtering out thinking blocks breaks the reasoning chain.
- Thinking blocks carry a `signature` field; in streaming they arrive as `thinking_delta` chunks. `reasoning_split` is a pure output-format switch and "does not enable or disable thinking".

## Prompting style
The former official page "M-series Usage Tips" (`token-plan/prompting-best-practices`) has been removed (HTTP 404, as of 2026-10-13) and has no successor in the docs; the following points are therefore only soft heuristics:
- **Task at the end**: source material first, question afterwards; index sources and delimit them with date/label; have the model cite or summarise the relevant passages before answering. (unverified)
- **Label sections** instead of running text: Task, Context, Source, Constraints, Output format — short labels with a colon or bold headings. (unverified)
- **Set reasoning depth in the prompt**: for planning, debugging, trade-offs and long-horizon work explicitly ask for deeper analysis; for extraction/classification conversely do not ask for explanation; do not request hidden chain-of-thought. (unverified)
- **Few-shot beats style abstraction**: 3–5 *diverse* examples for classification/extraction (relevant, with edge cases, concrete in the target format); repeating similar examples only burns tokens. (unverified)
- **Spell out the output contract**: section names, table columns, bullet caps, scope limits instead of vague requests such as "detailed" or "brief". (unverified)
- **Tool definitions** with purpose, inputs, return shape and failure behaviour, plus a when-*not*-to-use rule; set stop rules (e.g. stop after two failures and explain the blocker); parallel calls only for independent read-only lookups, workflows sequential. (unverified)
- **Reduce hallucinations**: explicitly allow refusal, require citation/source discipline, name permitted sources, time period and product version **before** the task. (unverified)
- **Supply intent** where a literally correct fulfilment could miss the actual purpose. (unverified)
- For long deliverables explicitly release the context window for use, and on long runs keep the work plan, status and open questions visible — one window per continuous task. (unverified)
- Only the sampling per the Hugging Face model card is confirmed: `temperature=1.0`, `top_p=0.95`.

## Strengths & weaknesses (prompt-relevant)
- Strengths: agentic coding and tool use (SWE-Bench Pro 59.0%, Terminal-Bench 2.1 66.0%, MCP Atlas 74.2%); 1M context based on MiniMax Sparse Attention (at 1M roughly 1/20 compute per token versus the previous generation, over 9× prefill and over 15× decode speedup); natively multimodal with image **and video** input; output speed approx. 100+ tps; very cheap ($0.30/$1.20 per 1M in the standard tier).
- **Price cliff at 512k input tokens**: above it the input, output and cache-read rates double. Chunking strategy matters more than pushing the window to its limit.
- Weaknesses/quirks: no documented effort grading (only `disabled`/`adaptive`) and no token budget — depth control is pure prompt work; `stop_sequences` and `top_k` are ignored on the Anthropic-compatible path; structured outputs or a JSON schema mode are not described in the docs for M3 (unverified) — format must be enforced via the prompt contract; no published knowledge cutoff (unverified). Open weights (Hugging Face, license minimax-community): ~428B parameters, ~23B active (MoE); self-hosting per the vendor "Experimental". The vendor blog describes the finance domain only as "initially usable" — do not rely on autonomous runs there.

## Output & format conventions
- Context window **up to 1,000,000 tokens**; via the API MiniMax guarantees only "a guaranteed minimum of 512K tokens". Self-hosted, 1M is only the model limit (SGLang validates 1K–128K). `max_tokens` (Anthropic path) or `max_completion_tokens` (OpenAI path): recommended 131072 (128K), maximum 524288 (512K); `max_tokens` is deprecated on the OpenAI path. Thinking tokens count against `max_tokens`; set too small → `stop_reason: "max_tokens"` with no text (Anthropic) or `finish_reason: "length"` with empty `content` (OpenAI).
- Model ID (API, exact spelling per the docs): `MiniMax-M3` — take it over into `model` as is; `minimax-m3` is only this repo's registry key.
- `temperature` default 1, range [0, 2]; `top_p` default **0.95** for M3 (0.9 for the M2.x models).
- Two endpoints: Anthropic-compatible `https://api.minimax.io/anthropic` — recommended as default by MiniMax, "Supports thinking blocks, interleaved thinking, and other advanced features" — and OpenAI-compatible `https://api.minimax.io/v1`.
- Self-hosted: without `--reasoning-parser auto` / `--tool-call-parser auto` raw `<mm:think>` or tool-call tokens end up in `content`.
- Prompt caching is **automatic/passive** from 512 input tokens; the TTL adapts to system load; prefix order `tool list → system prompts → user messages`. Static content first, dynamic user data at the end. Explicit caching via `cache_control` (Anthropic path) MiniMax documents only for the M2.x series; for M3 only passive caching is documented. The Messages schema does accept `cache_control` generically, but an effect on M3 is (unverified). Usage reports `cache_read_input_tokens`.
- Prices per 1M tokens (standard tier, per the docs "Permanent 50% off"): ≤512k input $0.30 / output $1.20 / cache read $0.06; >512k $0.60 / $2.40 / $0.12. Priority tier (`service_tier: "priority"`) 1.5× each.

## Migration notes
- **AWAY FROM MiniMax-M3**: resolve interleaved-thinking assumptions — target models that do not think between tool rounds need explicit step scaffolding again ("plan, call the tool, evaluate the result, decide"). Remove MiniMax-specific fields (`reasoning_split`, `reasoning_details`, `thinking: {"type": "adaptive"}`) and adapt history handling to the target, which may not accept thinking blocks at all. `top_p: 0.95` is an M3 default, not a universal value — use the target's own default there. `stop_sequences` and `top_k` become effective again with other providers: values that were previously sent without effect can now truncate answers. If the target has an effort/`budget_tokens` ladder, replace prompt-based depth control with the parameter instead of running both in parallel. With a window smaller than 1M, replace the task-at-the-end arrangement (unverified) with real retrieval/chunking. For Anthropic targets: set explicit `cache_control` breakpoints anew, since M3 only cached passively.
- **TO MiniMax-M3**: set `thinking` **explicitly** — the default flips between the two endpoints. Remove `budget_tokens`, `reasoning_effort`, `thinking_budget` and comparable depth parameters without replacement (M3 ignores them rather than erroring); anyone who needs real depth control should switch to MiniMax-M3.1-Flash-Preview (preview, only M Plan/MiniMax Code). Remove visible CoT scaffolding ("think step by step", "show your intermediate steps") when thinking is on, and instead set a reasoning-depth line. Rework multi-turn handling: write back the complete assistant message including thinking blocks — anyone who, as with other providers, keeps only text plus `tool_calls` loses the reasoning chain. Rename `max_tokens` to `max_completion_tokens` on the OpenAI path and limit it to ≤ 524288 (recommended 131072); be generous for thinking workloads. On the Anthropic-compatible path `stop_sequences` and `top_k` are ignored — move format control into the prompt (section names, columns, limits), since a schema mode is missing (unverified); for the OpenAI path the behaviour of `stop` here is not verified (unverified). Rebuild the prompt: source material **before** the task, label sections, add failure behaviour and stop rules to tool definitions (unverified — source removed). Check the cache layout (tools → system → user, static first), otherwise the prefix hit rate of automatic caching drops. Do not plan on `cache_control` breakpoints from Claude prompts being effective — base costs on passive prefix caching. Keep requests under 512k input — that is where both the guaranteed context size and the standard price end.
