# Claude Fable 5

## Reasoning / Thinking
- Type: **adaptive, always on**. Omit `thinking` or send `{type: "adaptive"}`; `{type: "disabled"}` and `{type: "enabled", budget_tokens: N}` both return 400. Depth is controlled solely via `output_config.effort` (`low | medium | high | xhigh | max`), default `high`.
- `effort` on Fable 5 is **request-level**: changing it between requests discards the cached prefixes of earlier turns. Per-message effort (beta `mid-conversation-output-config-2026-07-01`) is not supported — with the beta header, an effort system message returns 400. In cached conversations, keep effort constant.
- `thinking.display` defaults to `"omitted"` (empty thinking blocks); `"summarized"` returns a summary; the raw chain of thought is never returned. Text the model writes between tool calls arrives as a progress `thinking` block, not as a `text` block; interleaved thinking runs automatically.
- Return thinking blocks unchanged. Fable 5 blocks are readable only by Fable 5, Mythos 5, Fable 5.1 and Mythos 5.1; for any other model the API discards them before the model sees them and does not bill them.
- Non-default values for `temperature`/`top_p`/`top_k` → 400.

## Prompting style
- **Longer turns**: individual requests on heavy tasks run for many minutes at higher effort, and autonomous runs for hours — adjust client timeouts, streaming and progress indicators before migrating; check long runs asynchronously (e.g. via a scheduled job) rather than blocking while waiting.
- **Effort**: `high` as the default for most tasks, `xhigh` for the most capacity-critical workloads, `medium`/`low` for routine work — the docs say lower levels often outperform `xhigh` on predecessor models. At `high`/`xhigh`, set `max_tokens` generously (thinking and response share one limit).
- **Short instructions instead of lists**: instruction following is strong enough that one terse sentence can replace a whole list of behaviors. The docs supply ready-made system prompt snippets for: anti-overplanning ("when you have enough information to act, act"), no unrequested refactoring/tidying, result first instead of rambling, clarifying questions only for destructive actions/scope changes/missing input, checking progress claims against tool results, boundaries (for problem descriptions, only assess, don't fix), asynchronous parallel sub-agents, a memory file, and a readability addendum for the closing summary.
- Optionally a `send_to_user` tool for verbatim interim outputs from long agents — without an explicit invocation instruction in the system prompt it is rarely used; do not route narration or reasoning through it.
- **Trim migrated prompts/skills**: skills written for earlier models are often too prescriptive and can lower quality — check older instructions against the default performance and remove where needed. Give the reason for the request; ask explicitly for self-verification (separate verifier sub-agents with fresh context at a fixed interval rather than self-critique).
- **Do not request reasoning in the response text**: prompts, skills and tool descriptions that have the model write out its thinking/reasoning — verbatim or in a fixed format (a `<thinking>`, `<reasoning>` or scratchpad section before the answer, a `reasoning`/`thinking`/`trace` field in JSON output or tool input, a reasoning log, reasoning "verbatim"/"in full") — can be refused with `stop_reason: "refusal"` and `stop_details.category: "reasoning_extraction"`. Instead, request a short justification, the evidence, or a summary of the steps taken; if the reasoning itself is needed, keep thinking on and read the thinking blocks with `display: "summarized"`. This category has no fallback model (change the prompt rather than resending), and a refusal before any output is billed.

## Strengths & weaknesses (prompt-relevant)
- Strengths (at release, June 2026, versus Opus 4.8): long-horizon autonomy over multi-day, goal-directed runs; first-shot correctness on complex, well-specified problems; vision on dense technical images and screenshots (with Bash/crop tools also on rotated, blurred or noisy images); enterprise workflows (financial analysis, spreadsheets, slides, documents); code review and debugging; handling ambiguous, multi-threaded requests; reliable delegation to parallel sub-agents. According to the vendor, successor Fable 5.1 improves mainly on long agentic coding, research and document work.
- Weaknesses/quirks: at high effort on routine work, over-eager context gathering and deliberation; occasional unrequested actions (email drafts, backup branches); in long agentic conversations, hard-to-read shorthand (arrow chains, references to unseen thinking); deep into long sessions, rare early stopping with a statement of intent but no tool call, or unnecessary clarifying questions (counter with an autonomy reminder); rarely, context-budget worry (suggesting a new session/hand-off), usually triggered by a visible token countdown in the harness — avoid the countdown or use a reassurance reminder.
- Safety classifiers for offensive cybersecurity, biology/life sciences and extraction of thinking; even harmless work in these domains can trigger `stop_reason: "refusal"`. The model is not intended for offensive security and bio work.

## Output & format conventions
- 1M context window, 128K output tokens (synchronous Messages API); stream large outputs. Minimum cacheable prefix: 512 tokens. Tokenizer of the Opus 4.7 generation: roughly 30% more tokens for the same text compared with older models.
- No assistant prefill (400) — use Structured Outputs (`output_config.format`) or system prompt instructions instead. `tool_choice` accepts `auto`, `none`, `any` and `tool` (forced tool use is still possible here). Mid-conversation system messages and tool changes are supported.
- Refusals arrive as HTTP 200 with `stop_reason: "refusal"` and `stop_details` (`category`, `explanation`) — check before reading `content` and discard partial output. Since 24 Sep 2026, refusals before any output in the categories `bio`, `frontier_llm` and `reasoning_extraction` are billed; in other categories they are not; mid-stream refusals bill input plus output already streamed.
- **Fallbacks are opt-in** (beta, Claude API only; on Bedrock, Google Cloud and Foundry use the SDK middleware instead): `fallbacks: "default"` with header `server-side-fallback-2026-07-01`, or an explicit list such as `fallbacks: [{"model": "claude-opus-4-8"}]` (the list form also accepts `server-side-fallback-2026-06-01`). The docs name Opus 4.8 as the fallback target; the permitted targets are returned by the Models API as `allowed_fallback_models`.
- Prices per MTok: input $10, output $50, 5m cache write $12.50, 1h cache write $20, cache read $1 (0.1× input); batch 50% discount.
- Model IDs: Claude API, Google Cloud, Microsoft Foundry and Claude Platform on AWS `claude-fable-5`; Amazon Bedrock `anthropic.claude-fable-5`. Reliable knowledge cutoff Jan 2026.
- **30-day retention mandatory** (covered model): no ZDR without explicit authorization from Anthropic; on the Claude API, an organization without a matching retention configuration gets 400 `invalid_request_error`.

## Migration notes
- **Status**: according to the vendor, Fable 5 is legacy and Anthropic recommends moving to Claude Fable 5.1 (`claude-fable-5-1`); consider this target for new migrations. The model remains available (lifecycle status *Active (legacy)*, retirement not before 9 Jun 2027).
- **AWAY FROM Fable 5**: only Fable 5.1 (or Mythos 5/5.1) reads Fable 5 thinking blocks; on any other target they are discarded (not billed) and the model re-plans without the previous reasoning. Do not carry over effort settings; re-sweep on the target. Adjust refusal/fallback configuration to the target (`fallbacks` targets are model-specific). Prefill, sampling, forced tool use and ZDR follow the target's guide.
- **MIGRATING TO Fable 5**: remove every `thinking` configuration other than `adaptive` (including `disabled` and `budget_tokens`); remove non-default sampling and prefills; remove per-message effort system messages (400) and keep effort constant per cached conversation; ensure 30-day retention; add `refusal` handling and configure fallbacks explicitly; run an effort sweep including `medium`/`low` for routine work; adjust timeouts/streaming for long turns; remove over-prescriptive scaffolding and add short behavior snippets instead; review system prompts and skills for reflection/show-your-thinking instructions and replace them (`reasoning_extraction`, which `fallbacks: "default"` will not retry).
