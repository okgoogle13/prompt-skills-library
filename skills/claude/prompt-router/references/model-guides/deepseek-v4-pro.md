# DeepSeek-V4-Pro

## Reasoning / Thinking
- Hybrid model with one model ID: thinking is **active by default** with effort `high`. OpenAI format: `thinking: {"type": "enabled"|"disabled"}` (via `extra_body`) plus `reasoning_effort` `low|high|max` (`medium`/`xhigh` are mapped to `high`); Anthropic format: the same switch `thinking: {"type": "enabled"|"disabled"}` (`budget_tokens` is ignored), effort via `output_config: {"effort": "low|high|max"}`; Responses API: `reasoning: {"effort": "none|low|high|max"}` (`none` = off). `reasoning_effort` also accepts `none` (thinking off); mapping minimal→low, medium/xhigh→high, ultra→max. The model card names the levels Non-Think / Think High / Think Max; **for Think Max a context window of at least 384K tokens is recommended**, and the system prompt is prefixed with a text ("Reasoning Effort: Absolute maximum with no shortcuts permitted. You MUST be very thorough in your thinking …") — the prompt then competes with a thoroughness instruction; explicitly ask for concise answers.
- `reasoning_content` is returned alongside `content`. In pure multi-turn conversations it may be omitted (the API ignores it), but **across tool-call turns** it must be passed back.
- Thinking mode ignores `temperature`, `presence_penalty`, `frequency_penalty` (no error, no effect). `top_p` only has an effect in thinking mode (effectively 0.95–1.0, smaller values → 0.95); in non-thinking mode `top_p` is fixed at 1.0.

## Prompting style
- Prompting contract identical to V4-Flash (same API guides, same chat template). The system prompt is encoded directly after BOS: `<｜begin▁of▁sentence｜>{system}<｜User｜>{user}<｜Assistant｜>` — system instructions sit right at the front and are not a special block.
- Prefix caching runs automatically and only hits on a **full** prefix match of a cache unit (best-effort, no hit rate guaranteed): stable instructions and reference material first, variable input at the end (inferred from the examples — unverified).
- JSON: `response_format: json_object` **plus** the literal "json" and an example JSON in the system or user prompt; set `max_tokens` generously. No `json_schema` type is documented — structure is prompt-guided, not schema-enforced.
- Prefill via Chat Prefix Completion: last message `role: "assistant"` + `prefix: True` against `https://api.deepseek.com/beta`, optionally with `stop`. Local deployment: `temperature = 1.0`, `top_p = 0.95` agentic / otherwise 1.0 (0813 card); for `high`/`max`, a 384K max output is recommended.
- Tool calls are emitted in DSML markup (`<｜DSML｜tool_calls>` / `<｜DSML｜invoke>`) with `string="true"` for raw strings and `string="false"` for JSON-typed values. Since 2026-09-10 DeepSeek ranks V4.1-Flash ahead of V4-Pro ("ahead of V4-Pro on performance, cost, speed & total runtime"); Pro remains relevant mainly for knowledge-heavy prompts (base SimpleQA-Verified 55.2 vs. 42.3 for V4.1-Flash base).

## Strengths & weaknesses (prompt-relevant)
- Strengths: frontier tier (MoE 1.6T total / 49B active, hybrid attention from Compressed Sparse Attention + Heavily Compressed Attention, Manifold-Constrained Hyper-Connections, Muon optimizer, >32T training tokens). Benchmarks (Think Max): LiveCodeBench 93.5, Codeforces 3206, IMOAnswerBench 89.8, GPQA Diamond 90.1, MMLU-Pro 87.5, SimpleQA-Verified 57.9, MRCR 1M 83.5 — strong in coding, competition math/science, factual knowledge and 1M retrieval. Efficiency: 27% of the single-token inference FLOPs and 10% of the KV cache of V3.2 at 1M context.
- Weaknesses/quirks: throughput and price rather than capability — price per 1M tokens (peak / off-peak): input cache-miss $1.32 / $0.66, cache-hit $0.044 / $0.022, output $3.96 / $1.98 — approx. 4.4× (input) and 3.3× (output) `deepseek-flash`; 500 instead of 2500 parallel requests; peak = Mon–Fri 01:00–04:00 and 06:00–10:00 UTC. JSON mode occasionally returns empty `content`; FIM completion only in non-thinking mode; V4-Pro does not accept images (vision "Not supported"); the Anthropic endpoint generally does not support document blocks, and it lacks the `anthropic-beta`/`anthropic-version` headers, `top_k`, MCP and containers. The model card has no explicit limitations section.

## Output & format conventions
- 1M context window, up to 384K output tokens. Current version behind the ID: DeepSeek-V4-Pro-0813 (GA on 2026-08-13 for APP, web and API); the call path is unchanged — keep using `deepseek-v4-pro` for the latest version. A re-routing to V4.1-Flash announced on 2026-09-10 for starting 2026-09-14 was withdrawn per the change log — V4-Pro continues to run with unchanged billing; a V4.1-Pro has been announced, date unverified.
- Base URLs: `https://api.deepseek.com` (OpenAI SDK), `https://api.deepseek.com/anthropic` (Anthropic SDK, `claude-opus*` → `deepseek-v4-pro`), `https://api.deepseek.com/beta` (prefill); Responses API native (adapted for Codex).
- `response_format` `text|json_object`; `tool_choice` none/auto/required/specific — `required` and named tools return HTTP 400 in thinking mode (usable only with `thinking: disabled`); `max_tokens` defaults 8K (non-thinking) / 64K (thinking) / 128K (`max`), maximum 384K; up to 16 stop sequences; `top_logprobs` 0–20; `temperature` 0–2 (default 1), `top_p` 0–1 (default 1); `frequency_penalty`/`presence_penalty` deprecated and ineffective. Peak/off-peak billing from 16 Aug 2026 16:00 UTC (off-peak = half the peak price).

## Migration notes
- **Migrating AWAY FROM DeepSeek-V4-Pro**: remove `thinking`/`reasoning_effort` and all `reasoning_content` wiring; if the target has no native reasoning mode, write explicit CoT instructions back into the prompt; if the target supports `json_schema`, lift the in-prompt JSON example into a real schema and drop the mandatory literal "json"; translate DSML tool-call examples into the target's tool format; replace `prefix: True` with the prefill or stop-sequence equivalent; 1M/384K are not portable — plan chunking again.
- **Migrating TO DeepSeek-V4-Pro**: from `deepseek-chat`/`deepseek-reasoner` (retired since 2026-07-24 15:59 UTC) the rule is "keep base_url, only set `model` to `deepseek-v4-pro`" — however, the legacy IDs routed to **Flash**, so Pro is a deliberate upgrade. Prompt deltas: (1) former `deepseek-chat` prompts now need `thinking: {"type": "disabled"}` explicitly, since thinking is on by default; (2) remove `frequency_penalty`/`presence_penalty`; (3) strip temperature tuning from reasoning prompts — dead text in thinking mode (`top_p` only acts between 0.95 and 1.0 there); (4) in tool loops pass `reasoning_content` back instead of stripping CoT; (5) delete chunking/map-reduce scaffolding built for old V3/R1 windows and pass whole documents; (6) move static instructions to the front (prefix caching; inferred from the examples — unverified); (7) convert depth phrasing in the prompt text ("think step by step", "be thorough") into `reasoning_effort: low|high|max`; (8) forcing a tool via `tool_choice: required`/a named tool only works with `thinking: {"type": "disabled"}` — otherwise 400.
- **Pro ↔ Flash (`deepseek-flash` = V4.1-Flash)**: same API parameters and 1M/384K, but no longer the same template (V4.1: DSML tags with a leading space, numeric effort 1–100, mid-conversation system messages), and only Flash accepts images. Anthropic endpoint: Flash accepts subsequent system messages (`in-history`), Pro only the leading one (`leading-only`) — when switching to Pro, merge system updates into the leading system message. According to the vendor, agentic coding prompts run better on V4.1-Flash (TB 2.1 90.6 vs. 87.9, DeepSWE v1.1 74.2 vs. 62.7); use Pro only for knowledge-heavy prompts.
