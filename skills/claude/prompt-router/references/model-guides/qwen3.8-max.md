# Qwen3.8-Max

## Reasoning / Thinking
- Type: **hybrid, on by default**. The commercial Qwen3.8 series (max, flash, 27b) is listed on the deep-thinking page as "thinking mode enabled by default" (the open qwen3.8-2.4t-a95b there as "thinking mode only") — a request without a thinking field thinks. Turn it off per request with `enable_thinking: false`.
- Parameter placement depends on the SDK: in the OpenAI Python SDK `enable_thinking`/`thinking_budget` belong in `extra_body` (not a standard OpenAI parameter); in the Node.js SDK they are passed as top-level properties; in DashScope directly.
- `thinking_budget` caps the reasoning tokens; default per the API reference is the model's maximum chain-of-thought length — for qwen3.8-max **262,144 tokens** (the console shows a different default of 4,000, range 1–32,768). Once the budget is exhausted, the model stops thinking and answers immediately.
- Reasoning comes back in `reasoning_content`, the answer in `content`. In the history `reasoning_content` is ignored **unless** `preserve_thinking: true` is set (documented for qwen3.8-max) — then earlier reasoning flows into the input and is billed.
- Streaming is recommended because of latency but not required: commercial thinking models also support synchronous calls per the docs (the streaming-only restriction concerns open models such as qwen3.5-122b-a10b and qwen3.5-27b).
- Thinking costs context: max input 983,616 tokens in thinking mode versus 991,808 without; max output stays 131,072.
- Via the Anthropic-compatible Messages endpoint: `thinking: {type: "enabled" | "disabled"}`; depth is controlled by `output_config.effort`, for qwen3.8-max default `xhigh`, valid `xhigh`/`medium`/`low`; `max` and `high` map to `xhigh`. `budget_tokens` is marked "to be deprecated" (docs: use `effort` for new integrations). Whether thinking runs when the `thinking` field is missing on this endpoint is not stated on the page (unverified).

## Prompting style
- **There is no model-specific prompting page for qwen3.8-max.** Officially there is only Alibaba's generic prompt-engineering guide: a frame of Context, Objective, Style, Tone, Audience, Response; few-shot examples for consistent form; explicit step lists for complex tasks; rare delimiters (`###`, `===`, `>>>`) to separate sections. Anything beyond that is unverified for this model.
- Because thinking runs by default, depth control belongs in `thinking_budget`, not in the prompt text — "think step by step" scaffolding merely duplicates the built-in reasoning and lengthens the visible answer.
- JSON: in `json_object` mode the word **"JSON" must appear literally in the prompt** (case-insensitive); in `json_schema` mode it is not required. The docs still recommend describing field names, types and an example in the prompt.
- Build the prompt for caching: recurring content first, variable content last; for vision tasks put stable images/videos **before** the changing text question.
- For long agentic runs, provide the full task specification upfront — Alibaba explicitly positions the 0902 snapshot for "long-horizon autonomous development" and "multi-tool orchestration and end-to-end task delivery".

## Strengths & weaknesses (prompt-relevant)
- Architecture per the press release: 2.4 trillion parameters as **sparse MoE with a hybrid attention mechanism**, of which only 95B are active; 1M context; natively multimodal ("hundred-page documents, full television series, or 100-hour livestreams").
- Strengths: agentic coding and long-horizon work (internal test run: a real software project developed autonomously over 16 days); vision/chart reasoning and document parsing (further sharpened in the 0902 snapshot); Function Calling, Structured Outputs, Web Search (rolling id only in Beijing and Singapore, snapshot 0902 in all listed regions), Prefix Completion and Context Caching are enabled for the model; reachable via OpenAI-, Anthropic- and DashScope-compatible endpoints.
- Weaknesses/quirks: **no fine-tuning**; batch inference not available in some regions (e.g. Singapore, Germany, US, Japan); prefix continuation is documented only for the **non-thinking mode** — so prefill and thinking do not combine; the docs themselves warn that usable length "may vary depending on different combinations of API input parameters".
- Not published and therefore unverified: knowledge cutoff, recommended sampling parameters (`temperature`/`top_p`/`top_k`), behavior with out-of-range `thinking_budget`.

## Output & format conventions
- Context window 1,000,000 tokens; max input 991,808 (without thinking) or 983,616 (with); max output 131,072; max chain-of-thought 262,144. Input text/image/video, output text only.
- Structured output: `response_format` with `json_object` (keyword required) or `json_schema` with `strict: true`; the schema variant is explicitly documented for the Qwen3.8-Max series. Limitations per the structured-output page: `json_schema` is "not supported yet" for models in the Singapore region (the model page, by contrast, marks structured outputs in Singapore as supported — contradictory, test before production); multimodal inputs (image, video, audio) automatically fall back to `json_object` — then the "JSON" keyword requirement applies and there is no schema guarantee. On the Anthropic-compatible endpoint the same runs via `output_config` with `format.type: "json_schema"`, with strict enforcement for the 3.8/3.7 line.
- Prefix completion: last message with `role: "assistant"` and `partial: true`; the prefix is billed as input and the caller must concatenate it with the continuation.
- Context cache: implicitly active by default and **cannot be disabled**, minimum length **1,024 tokens**; explicit via `cache_control: {"type": "ephemeral"}`; validity 5 minutes, reset on each hit. Documented miss causes: expired cache block, more than 20 content blocks between the `cache_control` marker and the matching content, non-identical tool definitions (incl. tool and field order), and — implicitly — a differing prefix. The docs explicitly state that the hit rate is not 100% even with identical context.
- Price without length tiers across the full 1M window; reference Singapore $2 input / $6 output per 1M tokens, cache hits much cheaper (implicit cache input $0.25, explicit cache read $0.17). Other regions differ — see the model page.
- IDs: `qwen3.8-max` is the rolling alias, `qwen3.8-max-0902` (alias `qwen3.8-max-2026-09-02`, published 2 Sep 2026) is the pinned snapshot. The docs URL slug is `qwen3-8-max` — that is **not** the API id.
- The Anthropic-compatible endpoint offers only `/v1/messages`, no `/v1/models`: the model id must be configured manually in clients.

## Migration notes
- **AWAY FROM qwen3.8-max**: do not carry over Qwen-specific fields 1:1 — `enable_thinking`, `thinking_budget`, `preserve_thinking`, `reasoning_content`, `partial: true` prefill and `cache_control` markers are specific to Model Studio here; same-named or similar fields of other providers have different names, ranges and defaults — re-map or remove thinking control, prefill and caching against the target guide. If the target does not think on its own, write explicit reasoning/self-check steps back into the prompt. The 1M window shrinks on most targets — redesign chunking. Video input drops out on most targets. The "JSON" keyword requirement of `json_object` mode is a Qwen quirk and can be dropped; check the target's schema dialect and `strict` semantics. Cache rules (1,024-token minimum, stable prefix first) are Qwen figures and do not apply elsewhere.
- **TO qwen3.8-max**: the most important break — **thinking runs unless `enable_thinking: false` is set.** A prompt ported from a non-thinking model suddenly thinks: re-size latency, cost and `max_tokens`, and set `thinking_budget`, otherwise up to 262,144 tokens of chain of thought sit in the budget. Remove explicit CoT requests from the prompt and control depth via `thinking_budget`. For multi-turn, `preserve_thinking` decides whether earlier reasoning arrives at all — the default is to ignore it. If a route uses assistant prefill, set `enable_thinking: false` or switch to structured output (strict only without image/video input and — per the structured-output page — outside Singapore; otherwise only `json_object` with "JSON" in the prompt; partial mode is documented only for non-thinking). Coming from the Anthropic world: `thinking.type` works; replace `budget_tokens` with `output_config.effort`; an `effort: high`/`max` from Claude prompts lands here on `xhigh` (default, highest level), so set `medium` explicitly for moderate depth (the `thinking_budget` lever belongs on the OpenAI/DashScope route); the model id must be configured manually (no `/v1/models`). Put the stable prompt prefix first so the implicit prefix cache applies; for the explicit cache, tool definitions including order must stay identical across all requests. For reproducibility pin `qwen3.8-max-0902` instead of the rolling id (caution: the snapshot is capped at 150,000 TPM in Frankfurt/US/Tokyo/Hong Kong, while the rolling id has 5,000,000 there). Fine-tuning routes have no path here, and batch inference is not available in some regions either.
- Not to be confused: the versionless vendor id `qwen-max` is a separate, still-offered legacy model (functionally `qwen-max-2025-01-25`, 32,768 context, max output 8,192, no documented thinking mode) and **not** qwen3.8-max — a prompt for `model="qwen-max"` is not described by this guide. The same applies to `qwen-plus`/`qwen-flash` (separate hybrid models, thinking off by default per the deep-thinking page; see the qwen3.7-plus and qwen3.8-flash guides for the current tiers).
