# Doubao Seed 2.1 Pro

## Reasoning / Thinking
- Type: **deep thinking on by default**. `thinking.type` platform-wide knows `enabled | disabled | auto`, but doubao-seed-2-1-pro-260915 and -260628 appear in the support list only with `enabled` (default) and `disabled` — **no `auto`** (no model in the current support list lists `auto`; doubao-seed-1-6-250615 has been retired since 2026-09-21). A request without a `thinking` field thinks.
- Depth via `reasoning_effort` (Chat API) or `reasoning.effort` (Responses API). All seven levels are accepted: `none | minimal | low | medium | high | xhigh | max`; **default `high`**. Compatibility mapping per the docs: `minimal` switches thinking off, `none` is mapped to `minimal`, and **`xhigh`/`max` are mapped to `high`** — above `high` there is no real extra depth, only silent fallback without an error.
- Two ways to switch thinking off: `thinking: {"type":"disabled"}` or `reasoning_effort: "minimal"` / `"none"`.
- **Thinking summary is active by default** (verified for evolving, 2.1-pro-260915, 2.1-lite-260915, 2.1-pro-260628, 2.1-turbo-260628, 2.0-lite-260428): the raw chain-of-thought is not output; `choices.message.reasoning_content` (summary) and `choices.message.encrypted_content` (encrypted original) come back. `reasoning_effort` only affects the raw chain-of-thought, not the summary; billing is on raw tokens via `usage.completion_tokens_details.reasoning_tokens`.
- According to the docs, the summary noticeably increases package latency — raise `timeout` and design clients for it.
- Tool calling: **play back `encrypted_content`**; it takes precedence over `reasoning_content` and must be unchanged. According to the docs, returning only `reasoning_content` lowers inference quality in multi-turn/agent runs; returning nothing raises no error. In the Responses API, `previous_response_id` handles this automatically.
- Maximum chain-of-thought 256k tokens — it counts against the same output budget as the answer.

## Prompting style
Volcengine documents explicit "prompt optimization recommendations" for deep-thinking models; they invert the usual reflexes:
- **Goal, scenario and audience instead of task**: beyond the bare question, add language/tool requirements (English, Python), readership (primary school pupils, report to management), scenario (term paper, topic report, screenplay) and goal (demonstrate expertise).
- **Omit decomposition**: according to the docs, step-by-step instructions and examples should be reduced or avoided — they narrow the model's reasoning logic. Carried-over CoT scaffolding and few-shot blocks are actively harmful here, not merely superfluous.
- **Reduce system prompts**: the docs recommend putting all prompt information directly through the user prompt (`role: user`). This is the most conspicuous deviation from the role separation of other providers.
- **Format via the API, not via prose**: work with `response_format` (`json_schema`, `strict: true`) and in the prompt neither stress "output JSON" nor repeat the schema structure — the docs call this contradictory and redundant; describe the content instead.
- **Drop `frequency_penalty`/`presence_penalty`** when structured output is active — the docs warn twice about abnormal outputs.

## Strengths & weaknesses (prompt-relevant)
- Strengths per capability table: deep thinking, text generation, multimodal understanding (input text, image, video; output text), **GUI task handling**, tool calling and structured output. Full tool stack: function calling (Chat + Responses), knowledge base, MCP, web-search plugin, image processing and Doubao assistant (the last five only via the Responses API).
- Positioning per the ByteDance announcement: agent reliability across multi-step workflows (project planning, document processing, tool use), end-to-end coding delivery across the enterprise cycle (requirements analysis, implementation, bug fixing, setup, validation) and multimodality. Seed2.1 Pro reaches the top score on GDPVal there, a top-tier score on Agents' Last Exam, and the highest scores on CharXiv-RQ and MeasureBench (document/chart/numeric understanding); on TVBench and TOMATO the blog explicitly only claims top-tier levels ("industry-leading levels"), not a highest score. The MobileWorld highest score and the 16% fewer steps on average to task completion are attributed by the blog to the "Seed2.1" series, not explicitly to the Pro variant. The 260915 release, according to the release note, advertises stronger autonomous planning, long-chain execution and dynamic repair.
- Weaknesses/quirks: **rate limits 500 RPM / 1,000,000 TPM** — the 2.0 generation and Seed 2.1 Lite are at 30,000 RPM / 5,000,000 TPM, a significant throughput drop when moving up. **Default response length 4k** despite the 256k ceiling. Structured output is explicitly **beta** (availability fluctuates; production use only after testing) and not usable at all with TPM guarantee packages. No `auto` thinking, no effort level above `high`. No official knowledge cutoff published (unverified).
- Availability: Pro is documented only on Volcengine Ark (China). On BytePlus ModelArk (international), the 2.1 series lists only `dola-seed-2-1-turbo-260628` — a Pro variant is not documented there.

## Output & format conventions
- Model ID: `doubao-seed-2-1-pro-260915` (Ark: 首推 = top pick; per the model page identical to the doubao-seed-evolving state of 9 Sep 2026); `doubao-seed-2-1-pro-260628` now only appears under 往期模型 (past models). 260915: context window 1024k, max input 1024k (260628: 256k/256k); both max response 256k with **default 4k**, max chain-of-thought 256k. `doubao-seed-evolving` is a rolling ID with at least weekly updates — pin the dated snapshot for reproducible migrations. The undated form `doubao-seed-2.1-pro` appears only as a billing name on the pricing page; as a callable model ID it is not verified (unverified).
- Output length via `max_completion_tokens` (Chat API) or `max_output_tokens` (Responses API) — the limit covers chain-of-thought **plus** answer.
- Structured output: `json_schema` with `strict: true` is the recommended mode; `json_object` is the predecessor and requires the string `json` in the input. Field order follows the schema order; `$ref` only as a local `#` reference; `oneOf` without a guarantee of "exactly one" semantics and `allOf` without a guarantee of "all" semantics (`anyOf` is listed without caveat); unsupported keywords throw an error.
- Operations: streaming recommended; in non-streaming operation set `timeout` above 30 minutes (Ark Go SDK always, even with streaming).
- Caching: implicit caching via Responses API and Chat API, explicit caching via the Responses API (prefix cache, session cache).
- Prices Volcengine (online inference, full 0–1024k **without a length tier**, unlike doubao-seed-2.0-pro): 6.00 ¥ input, 1.20 ¥ cache hit, 30.00 ¥ output per million tokens; cache storage 0.017 ¥ per million tokens/hour. Batch inference: 3.00 ¥ / 1.20 ¥ / 15.00 ¥. Low-priority (flex): 3.00 ¥ / 1.20 ¥ / 15.00 ¥ (implicit caching only). `doubao-seed-evolving` costs the same as Pro in the online tier.
- Multi-turn: from doubao-seed-1.8 onward, the `reasoning_content` of prior rounds is supposed to **remain** in the conversation, and the model decides for itself how to use it; only models before 251228 had the field actively removed.

## Migration notes
- **AWAY FROM doubao-seed-2.1-pro**: `thinking.type`, `reasoning_effort`/`reasoning.effort` and the `encrypted_content` return are Ark-specific here (only `enabled|disabled`, `xhigh`/`max` → `high`, precedence of `encrypted_content`) — same-named fields from other providers have different enums and defaults; map thinking control onto the target guide anew instead of copying it 1:1 or removing it wholesale. Because CoT scaffolding and few-shot examples were deliberately removed here, "think step by step" instructions, examples and explicit verification steps must be **re-added** once the target is not an always-on reasoner. Reverse the Ark recommendation to put everything in the user prompt and separate roles cleanly again. Translate `response_format`/`json_schema` into the structured-output form of the target. Recalculate context (1024k for 260915, 256k for 260628), prices and the low RPM ceiling.
- **TO doubao-seed-2.1-pro**: (1) remove reasoning-forcing prompt lines — the model thinks by default, and decomposition instructions narrow it according to the docs. (2) Set `reasoning_effort` explicitly; values carried over from providers with `xhigh`/`max` silently land on `high`, without error and without extra depth — rerun the depth sweep instead of adopting defaults. (3) Fast paths need `thinking: {"type":"disabled"}` or `reasoning_effort: "minimal"`; there is no adaptive `auto` here, so each route must decide for itself. (4) Set `max_completion_tokens` or `max_output_tokens` — the 4k default cuts off, and the chain-of-thought counts. (5) Slim down the system prompt and add goal, audience and scenario instead. (6) Move format requirements from the prompt into `response_format` and remove `frequency_penalty`/`presence_penalty`. (7) In tool chains pass `encrypted_content` through, or switch to the Responses API with `previous_response_id`. (8) Enable streaming or raise the timeout above 30 minutes. (9) Adjust concurrency assumptions to 500 RPM / 1M TPM. (10) For international deployments check: there only Turbo is available from the 2.1 series (see doubao-seed-2-1-turbo). (11) Pin the snapshot: Ark specifies a 3–6 month lifecycle per version (model deprecation page); use `doubao-seed-evolving` only deliberately as a rolling pointer.
