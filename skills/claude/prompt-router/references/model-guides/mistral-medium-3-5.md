# Mistral Medium 3.5

## Reasoning / Thinking
- Type: **switchable per request** via `reasoning_effort`. Officially documented are exactly **two** values, `"none"` and `"high"` — the official chat template aborts with `reasoning_effort must be either "none" or "high"` for any other value. No intermediate levels, no token budget, no `thinking` object.
- **Default is `"none"`**: if the field is missing, the template sets it to `none` itself. A prompt carried over unchanged therefore runs without reasoning — the control must be set explicitly.
- `"high"`: "The response includes a full thinking chunk before the final answer, at the cost of increased token usage." `"none"`: "The model thinks minimally and the thinking chunk is omitted from the response."
- Vendor recommendation: "For agentic and code use cases, `reasoning_effort="high"` is recommended" — likewise for complex prompts.
- Sampling is **coupled to the mode**: with `"high"` `temperature` 0.7 and `top_p` 0.95; with `"none"` `temperature` 0.0–0.7 (the official example code uses 0.1) and `top_p` set to `None` or 1.0.
- Multi-turn requirement with an explicit warning: replay the complete assistant message **including `ThinkChunk`** into the history. "Do not strip ThinkChunk from assistant messages before replaying them. … Stripping them increases token efficiency but significantly degrades output quality."
- `reasoning_effort` also applies on `/v1/agents` and `/v1/conversations`, there in the field `completion_args`.

## Prompting style
- **System prompt is the primary control surface**: the vendor card lists "System Prompt: Strong adherence and support for system prompts" as its own capability, and all official usage examples load the `SYSTEM_PROMPT.txt` shipped in the repo as the system message.
- Role-first framing from the official prompting docs: "You are a <role>, your task is to <task>."; structure instructions hierarchically into sections and subsections, and write as if writing "for someone with no prior context".
- Structure via **Markdown and/or XML-like tags** (the docs' rationale: "Readable", "Parsable", "Familiar"). Few-shot either as a `# Examples` section or as artificial user/assistant turns. System = general context, user = context of the current interaction; without a system role, concatenate both into the user turn.
- Prompt agentically and schema-driven: the vendor positions the model for "long-horizon tasks, calling multiple tools reliably, and producing structured output that downstream code can consume" — pass tool definitions cleanly as schemas instead of re-explaining them in prose.
- Plan for literalness: "Mistral Medium 3.5 can follow your instructions to the letter." Spell out scope, stop conditions and output form instead of hoping for interpretation.
- Documented anti-patterns of the prompting docs: vague quantitative adjectives ("too long", "many"), fuzzy words ("things", "interesting", "better"), contradictory rules (use a decision tree instead), having the model count (pass character counts as input), generating unnecessary output tokens, numeric 1–5 scales (use word scales such as "Very Low" … "Very Good").

## Strengths & weaknesses (prompt-relevant)
- "Our first flagship merged model": instruction following, reasoning and coding in **one** weight set — dense 128B, 256k context, open weights under Modified MIT, per the announcement self-hostable "on as few as four GPUs".
- Agentic and coding are the documented strength: 77.6% on SWE-Bench Verified and 91.4 on τ³-Telecom; "supersedes all our previous coding models, namely Devstral, across all benchmarks".
- Vision: the vision encoder was trained "from scratch" for **variable image sizes and aspect ratios** — the ~1:1 cropping documented for Mistral Large 3 is not needed here. Text + image in, text out. Multilingual: the vendor card says "dozens of languages" in prose (example list includes English, French, Spanish, German, Chinese, Japanese, Arabic); the number 24 comes from the repo's language tags, not from the running text.
- Cost is the real weakness: $1.5 input / $0.15 cached input / $7.5 output per 1M tokens — at the same 256k window, three times the input price and **five times** the output price of Mistral Large 3 ($0.5 / $0.05 / $1.5). `reasoning_effort: "high"` additionally increases output tokens.
- Knowledge date: the official default system prompt says "Your knowledge base was last updated on Friday, November 1, 2024" and instructs the model to use tools for current or specific data. Mistral publishes no separate knowledge cutoff (unverified).
- Maximum output token limit: not officially documented (unverified).

## Output & format conventions
- Context window 256k. Three official API strings: `mistral-medium-3-5` (fixed major.minor), `mistral-medium-3` (newest minor of this major generation), `mistral-medium-latest` (per lifecycle docs "Latest version, across generations"). Docs warning: "Using an alias may expose you to silent updates in model behavior and pricing. For precise control, pin your deployment to a specific major.minor version identifier." Whether an alias moves only with the GA stage of a new model, the page does not say (unverified) — for reproducible prompts pin to `mistral-medium-3-5`.
- There is **no** date-stamped id for this generation: predecessors were `mistral-medium-2508` / `mistral-medium-2505`; from 3.5 on, the `model-name-major-minor` scheme applies. Aggregator ids in the style `mistral-medium-26xx` are not vendor ids.
- Response form depends on the mode: with `"high"`, `message.content` is **not a string** but a list of `ThinkChunk` (`type: "thinking"`) and `TextChunk` (`type: "text"`); with `"none"` a plain `str`. In streaming, `delta.content` is first a list (thinking), then a transition chunk with a closing `ThinkChunk` plus the first `TextChunk`, then a plain string.
- Features per model card: Structured Outputs, Function Calling, **Predicted Outputs**, Document QnA, Prefix (assistant prefill), Batching, Agents & Conversations, Chat Completions, Built-In Tools — Mistral Large 3 does not offer Predicted Outputs.
- Self-hosting template markers: `[SYSTEM_PROMPT]…[/SYSTEM_PROMPT]`, `[INST]…[/INST]`, `[AVAILABLE_TOOLS]`, `[MODEL_SETTINGS]{"reasoning_effort": …}[/MODEL_SETTINGS]`, `[THINK]…[/THINK]`, `[TOOL_CALLS]<name>[ARGS]<json>`, `[TOOL_RESULTS]…[/TOOL_RESULTS]`, `[IMG]`. Only the roles `user`, `assistant`, `system`, `tool`; the conversation must start with `user` or `system`; images are only allowed in user and tool messages, not in system or assistant messages.
- vLLM serving per vendor card: `--tool-call-parser mistral --enable-auto-tool-choice --reasoning-parser mistral`; via the OpenAI-compatible interface the reasoning trace then sits in `message.reasoning`.

## Migration notes
- **AWAY FROM Mistral Medium 3.5**: remove `reasoning_effort` and the entire thinking-chunk handling — goals without a reasoning control need explicit step-by-step / chain-of-thought scaffolding in the prompt again. Recalibrate the mode-coupled sampling values (0.7 / 0.95 or 0.1 / `None`); they apply only here. Switch response parsing back to a plain string and drop the replay rule for `ThinkChunk`. Replace Mistral specifics: prefix prefill, Predicted Outputs, built-in tools, `/v1/conversations` and `completion_args`. For targets below 256k, re-plan the context budget; for text-only targets, remove image content parts.
- **TO Mistral Medium 3.5**: it is Mistral's **own replacement path** for `mistral-large-2411`, `pixtral-large-2411`, `mistral-medium-2508`, `mistral-medium-2505`, `devstral-2512`, `devstral-medium-2507` and the whole `magistral-medium-*` series — set the target id accordingly. **Set `reasoning_effort` explicitly**: without the field the prompt runs on `none`, so a prompt carried over from Magistral (a native reasoner) silently loses its reasoning; for agentic and code use `"high"`. Conversely, coming from Mistral Large 3: there is no such control there, so hand-written chain-of-thought can be dropped with `"high"`, and the Large 3 recommendation of `temperature` < 0.1 should be raised to 0.7 / `top_p` 0.95. Rebuild response parsing around the chunk list and carry `ThinkChunk` across all turns. Image preprocessing to ~1:1 is no longer needed. Hand-parsing of `[THINK]` tags taken over from Magistral should be replaced by `ThinkChunk`. Recalculate costs: output costs five times Large 3, plus reasoning tokens. Check provenance: Mistral Large 4 (`mistral-large-4-0`) and Mistral Small 4 (`mistral-small-latest`) also accept `reasoning_effort` — so a prompt with this field may come from there too.
