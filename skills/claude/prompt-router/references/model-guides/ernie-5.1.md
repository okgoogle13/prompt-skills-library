# ERNIE 5.1 (文心 5.1)

## Reasoning / Thinking
- **No documented on/off switch.** ernie-5.1 appears on neither the `enable_thinking` nor the `thinking` support list of the deep-thinking docs. The only ERNIE 5 model with `enable_thinking` is `ernie-5.0-thinking-preview` (there default `true`, can be switched off; the ernie-5.0 line is retired on 2026-10-29). For ernie-5.1, `enable_thinking: false` is **not verified** — do not rely on forcing a fast path without reasoning.
- **`thinking_budget` is listed**: support list `ernie-5.1, ernie-5.0-thinking-preview（仅思考模式生效）, deepseek-v3.2-think`. Minimum 100; default is contradictory: the deep-thinking page names the model-dependent chain-of-thought length, the API reference (status 2026-09-29) names 16384 (maximum = model-dependent length, not stated for ernie-5.1). If the chain-of-thought exceeds the budget, it is truncated and the answer starts immediately — this is the only documented depth lever.
- **Counter-evidence**: the model list (CN 2026-10-08, intl 2026-09-07) states under its ERNIE deep-thinking table that ERNIE thinking models do not support `thinking_budget`. ernie-5.1 is not in that table, but the note already contradicts the deep-thinking list for ernie-5.0-thinking-preview. Treat `thinking_budget` for ernie-5.1 as documented but not reliable, and test its effect.
- The qualifier "仅思考模式生效" (only effective in thinking mode) is attached in this list **only** to ernie-5.0-thinking-preview, not to ernie-5.1 — so the budget applies here without a mode coupling. Baidu nowhere explicitly states that thinking is therefore permanently on (unverified).
- ernie-5.1 is missing from the deep-thinking table of the model list and therefore has **no stated chain-of-thought length**. The circulating 60k chain-of-thought figure belongs to the ernie-5.0 line (ernie-5.0, -thinking-preview, -thinking-latest), not to 5.1 (the ernie-5.0 line is retired on 2026-10-29).
- `thinking_strategy` (`short_think`, `chain_of_draft`) is verified only for `deepseek-v3.2-think` — not available for ernie-5.1.
- The chain-of-thought comes back as a separate field `reasoning_content` **alongside** `content` (in the stream as `delta.reasoning_content`). Parsers that read only `content` lose it silently.
- Interleaved thinking (交错思考: passing `reasoning_content` back between tool calls) is not listed for ernie-5.1 (only deepseek-v3.2, ernie-5.0, ernie-5.0-thinking-preview).
- **Output ceiling**: `max_completion_tokens` is verified per the context-management docs only for DeepSeek models, **not** for ernie-5.1. `max_tokens` is per the API reference (status 2026-09-29) the total output **including** the chain-of-thought; the model list says the same for ERNIE thinking models. The older context-management page (2026-04-03) still describes `max_tokens` as response length without chain-of-thought. The sources contradict each other, so size `max_tokens` generously as a total ceiling (reasoning + answer).

## Prompting style
- Baidu publishes **no model-specific prompting guide** for ernie-5.1. Reliable are the API contract, a positioning sentence in the model list and Baidu's release post of 2026-05-09; any style statement beyond that is unverified.
- Official positioning: "文心系列最新模型，基础能力全面升级，在智能体、知识、推理、深度搜索等方面均有显著提升" — agents, knowledge, reasoning, deep search. The model line does **not** name further use cases — the list of 复杂语义理解 / 中文知识问答 / 文学创作 / 文档理解 / 中文数学题 (complex semantic understanding / Chinese knowledge QA / literary creation / document understanding / Chinese math problems) in the same table belongs to the `ernie-4.5-turbo-128k` row, not to ernie-5.1; it may not be claimed for 5.1. In addition, the release post advertises creative writing (long-form narrative, specialist texts) as a core strength, close to Gemini 3.1 Pro according to internal evals (vendor claim). The 文学创作 (literary creation) list of the model list nevertheless remains assigned to the ernie-4.5-turbo-128k row. Coding agentics are not stated for 5.1.
- **Do not force format via free-text schema.** Strict structured outputs (`response_format: json_schema` with `strict: true`) do not list ernie-5.1. Reliable are function calling (verified supported) or `response_format: json_object` **plus** a schema spelled out in the prompt.
- Standard roles `system` / `user` / `assistant` / `tool` via the OpenAI-compatible endpoint `https://qianfan.baidubce.com/v2/chat/completions` (OpenAI SDK with `base_url=".../v2"` works). System prompt as the first `system` message; Qianfan documents assistant prefill (对话前缀续写: `"prefix": true` on the last assistant message), but only for DeepSeek and Qwen3 models; ernie-5.1 is not on the support list, so no prefill.
- Do not prompt research behavior yourself: `web_search` is verified for the ERNIE 5.1 series (`enable`, `enable_citation`, `enable_trace`, `enable_status` each default `false`; `search_mode` default `auto`; `search_number`/`reference_number` default 10). Switch on citation duty via `enable_citation` rather than requesting it through prompt rules. Forced search is not possible: the docs state that ERNIE models do not support 强制搜索 (forced search, `search_mode: required`).
- Keep tool descriptions short: per the docs, function calling costs roughly **300 extra tokens** through internal prompt templating.

## Strengths & weaknesses (prompt-relevant)
- Strengths: 128k context with 119k max input and up to **65,536 output tokens** — a long source document and a long deliverable fit in the same call; function calling fully verified (`tools`, `tool_choice` `auto|none|required` or a specifically named tool object, parallel calls, return via `role: "tool"` + `tool_call_id`); integrated Baidu web search with citations; very low price (see below); officially positioned for agentics, knowledge, reasoning and deep search; creative writing (release post, internal evals).
- Weaknesses/quirks: **no `json_schema` strict mode** — no hard schema guarantees; **no prefix cache** (the prefix-cache list covers only DeepSeek models), so long repeated system prompts are fully billed every time; **no batch price** (the batch cell of the price table is empty → no batch discount); low default rate limit **RPM 60 / TPM 150,000**; not listed under visual understanding or native multimodality — treat as a **text-only model** despite the natively multimodal 5.0 line (unverified); listed on the Chinese and (since 2026-09-07) also the international English Qianfan model list, with identical limits (128k / 119k / [1, 65536], RPM 60 / TPM 150000); no published knowledge cutoff (unverified); no official recommendation for `temperature`/`top_p` (unverified).

## Output & format conventions
- Context window 128k, max input 119k, max output range `[1，65536]`; default flow-control RPM = 60, TPM = 150000.
- Response structure: `message.content`, alongside `reasoning_content` and optionally `tool_calls`; streaming via `delta`.
- `response_format`: `text` (default), `json_object`, `json_schema` — the API reference excludes only the ERNIE-X1-Turbo series in general, but `json_schema` strict support is not listed for ernie-5.1. `json_object` is the reliable path.
- `penalty_score` range 1.0–2.0, default 1.0 (the exclusion list of the API reference names, among others, the ERNIE-X1-Turbo and ERNIE-4.5 series as well as several DeepSeek models; ernie-5.1 is not on it); `seed` available for deterministic sampling.
- Prices in 元 per 1,000 tokens, tiered by **input length**: input ≤32k → 0.004 input / 0.018 output; 32k < input ≤128k → 0.006 input / 0.022 output. The tier therefore also raises the output price; align chunking decisions with the 32k boundary. There is no cache-hit price column for ernie-5.1; the batch cell is empty (—).

## Migration notes
- **AWAY FROM ernie-5.1**: `thinking_budget` is implemented here in a Qianfan-specific way (minimum 100, no stated chain-of-thought length for 5.1) — budget parameters of other providers have different ranges and defaults; map onto the `reasoning_effort`/`thinking` equivalents of the target and recalibrate depth, since no chain-of-thought length is stated for 5.1; replace `reasoning_content` parsing with the reasoning format of the target; the platform `web_search` object including `enable_citation` falls away — research and citation rules must be rebuilt as a tool or prompt rule; if the target can produce true `json_schema` strict output, move the schema description written in the prompt there and remove it from the text; the 32k price tier disappears — reassess the chunking strategy; for agent-, knowledge-, research- and creative-writing-heavy prompts, cross-check quality, since these are the officially advertised axes (智能体, 知识, 推理, 深度搜索 per the model list; creative writing per the release post).
- **TO ernie-5.1**: **remove** `enable_thinking` / `thinking: {type: ...}` — neither is verified for ernie-5.1; whoever previously switched reasoning off has no documented path to do so here and must instead limit it via a small `thinking_budget` (minimum 100) (test the effect; docs contradictory). Remove `thinking_strategy` (DeepSeek only). Size `max_tokens` anew as a total ceiling including the chain-of-thought; remove `max_completion_tokens` (not verified for ernie-5.1). Remove `prefix: true` prefills and passing `reasoning_content` back between tool calls. Rebuild strict `json_schema` routes as `json_object` + schema in the prompt, or as function calling. Drop prefix/prompt-cache assumptions: long system prompts are fully billed here — keep them short or reduce context per call. Remove image inputs. An ERNIE-VL fallback target is no longer verified from 2026-10-29: Baidu then retires ERNIE-5.0 (incl. thinking variants) and ERNIE-4.5-Turbo-VL-128K/-32K and names DeepSeek-V4.1-Flash as the replacement, not ernie-5.1. Dimension concurrency against RPM 60 / TPM 150,000. Replace your own web-search tools with the native `web_search` object and set `enable_citation`, instead of requesting citations via the prompt.
- **Lifecycle**: Baidu names ernie-5.1 as the official replacement for ERNIE-X1.1 / X1.1-Preview, retired on 2026-09-29. In the retirement register (status 2026-09-24) ernie-5.1 itself has no retirement date.
