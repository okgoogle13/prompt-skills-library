# Claude Sonnet 5.5

## Reasoning / Thinking
- Type: **adaptive, on by default** — a request without a `thinking` field thinks (same as `{type: "adaptive"}`). `thinking: {type: "disabled"}` returns **400** (`invalid_request_error` referring to `between_tools`); `{type: "enabled", budget_tokens: N}` also returns 400.
- The lowest setting is `thinking: {type: "between_tools"}`: it switches off up-front thinking, allowed only at effort `low`/`medium`/`high` (at `xhigh`/`max` → 400), and accepts no further field (`display`, `budget_tokens`, `block_binding` → 400). Without tools, the response then contains only text; with tools, progress notes still come as `thinking` blocks with summary text.
- Effort levels `low | medium | high | xhigh | max`, default `high`. The levels are **recalibrated compared with Sonnet 5** — do not carry settings over; run a fresh effort sweep. Starting values per the docs: `high` in general; `medium` for well-specified agentic coding/multistep tool tasks (`high` for harder/longer ones); `medium` or `low` for chat and latency-critical work; `xhigh`/`max` only with a measured quality gain.
- From `medium` upward the model briefly thinks before almost every answer (even at a greeting); a system prompt request to think less does not work reliably — lower effort instead. At `low`, thinking is skipped for most simple requests.
- `max_tokens` caps thinking **plus** the response, even when the thinking content is not returned; for agentic coding set 128,000 and stream.
- Changing top-level effort between requests invalidates the prompt cache. **Per-message effort** (beta `mid-conversation-output-config-2026-07-01`, on the Claude API and Google Cloud, not on Amazon Bedrock) keeps the cache, but requires adaptive thinking — with `between_tools`, a differing per-message effort returns 400.
- `thinking.display` defaults to `"omitted"` (empty blocks); `"summarized"` for readable summaries.
- Non-default `temperature`/`top_p`/`top_k` → 400 on every request (`top_p` default 0.99, so `top_p: 1` → 400, likewise `temperature` and `top_p` together).
- **Thinking blocks are bound to model and conversation**: Sonnet 5.5 reads blocks from Sonnet 5, Opus 4.8, Haiku 4.5 and older models, plus (Claude API/Google Cloud) Haiku 5.5, but not from Opus 5, Opus 5.5 or Fable/Mythos models; Sonnet 5.5 blocks are readable only by Opus 5.5 (Claude API/Google Cloud). A block after a change to `system`, `tools` or earlier messages → 400 (default for accounts from 31 Aug 2026); blocks are also bound to the generating account.

## Prompting style
- According to Anthropic, existing **Sonnet 5 prompts run well unchanged**; the patterns from "Prompting Claude Sonnet 5" remain a sensible starting point. For the hardest long-horizon work, the docs recommend an Opus model.
- **Steer initiative**: at `low`/`medium` the model more often pauses to ask questions before finishing in agentic coding — first raise effort, otherwise add the docs line "Keep working until everything the user asked for is done …" to the system prompt. Against unrequested tests/docs/helper files (at every level, more at high effort) add only the second paragraph ("When the work the user asked for is done and checked, stop and report …").
- At `xhigh`/`max` it starts its own review/verification rounds after finishing (possibly with sub-agents) — run routine work at `high` or below, or add the docs line against extra review rounds. For open-ended requests ("show what you can do with it"), state explicitly when you want only ideas or a plan first.
- **Phrase tool triggering in the prompt**: forced `tool_choice` no longer exists, so state in the prompt when a tool applies. In chat/knowledge work, remove tool-inhibiting phrasing ("only use tools when strictly necessary", "minimize tool calls") and, when a search tool is available, instruct it to actively look up changing details.
- **JSON answers for calculation/rule tasks**: at `low`/`medium` the model often answers without prior thinking. With Structured Outputs, put "Think the problem through before you answer." at the end of the system prompt or use `xhigh`; use adaptive thinking instead of `between_tools`; without Structured Outputs, parse the **last** JSON value in the response.
- With `between_tools`, avoid "don't think" instructions — they make internal XML tags in the visible output more likely. Replace manual chain-of-thought prompting with thinking.
- **Progress updates**: remove lines such as "hold all findings for the final response" and describe the desired update points (opening line, closing recap) in the system prompt; for exact interim text, declare a simple "message to user" tool in the first request. If it stays too quiet, after about five silent tool steps append a one-time turn-scoped system message as a reminder (stop after two or three attempts).
- **Mid-turn user input**: never put it in a `tool_result` block (otherwise it may be treated as possible prompt injection); append it as a text block after the last `tool_result` of the same user message, and send harness hints separately as a mid-conversation system message; do not add your own token countdowns after tool results in interactive sessions.
- **Verification**: at `low` it sometimes reports changes as done without a real test/build run — add the docs' verification rule ("run a real check that exercises the change before reporting it done …").
- **Do not request reasoning in the response text**: prompts, skills and tool descriptions that have the model write out its thinking/reasoning — verbatim or in a fixed format (a `<thinking>`, `<reasoning>` or scratchpad section before the answer, a `reasoning`/`thinking`/`trace` field in JSON output or tool input, a reasoning log, reasoning "verbatim"/"in full") — can be refused with `stop_reason: "refusal"` and `stop_details.category: "reasoning_extraction"`. Instead, request a short justification, the evidence, or a summary of the steps taken; if the reasoning itself is needed, keep thinking on and read the thinking blocks with `display: "summarized"`. This category has no fallback model (change the prompt rather than resending), and a refusal before any output is billed.

## Strengths & weaknesses (prompt-relevant)
- Strengths: according to Anthropic, the best combination of speed and intelligence in the current lineup (latency "Fast"); in agentic coding it usually checks its own work; reads dense charts and technical drawings much more accurately with crop/zoom/code tools (for charts, tools have more impact than more effort; for drawings only from `high`).
- Weaknesses/quirks: asks questions before finishing at `low`/`medium`; unrequested additions and extra review rounds at high effort; in chat/knowledge work sometimes answers from training knowledge instead of searching; occasionally calls tools with wrong capitalization or slightly different parameter names (make the harness tolerant or return `is_error: true` with the exact name); may treat genuine mid-turn messages as injection.
- Safety classifiers with five `stop_details` categories: `cyber`, `bio`, `frontier_llm`, `reasoning_extraction`, `general_harms` (the last can also hit harmless work). Server-side fallback (`fallbacks: "default"`, beta, Claude API only) retries `cyber`/`frontier_llm` on Sonnet 5, but not `bio`, `reasoning_extraction`, `general_harms`.

## Output & format conventions
- 1M context window, 128K output tokens (synchronous); Message Batches API up to 300K with beta header `output-300k-2026-03-24`.
- Prices per MTok: $2 input / $10 output, 5m cache write $2.50, 1h cache write $4, cache read $0.10 (half of the Sonnet 5 rate); batch −50%. Minimum cacheable prompt 512 tokens (Sonnet 5: 1,024).
- Tokenizer as Sonnet 5 (roughly 30% more tokens than Sonnet 4.6/Haiku 4.5). High-resolution images up to 2,576 px on the long edge or 4,784 visual tokens per image.
- **Forced tool use → 400**: `tool_choice` `{"type": "any"}`/`{"type": "tool", ...}` are rejected (also on the token-counting endpoint); `auto` and `none` work. For schema-valid tool input use `auto` plus `strict: true` or Structured Outputs; on Amazon Bedrock, Structured Outputs/strict are not available for Sonnet 5.5 → use `auto` without `strict` and validate input in code.
- **Text between tool calls** arrives (from one or two sentences) as a progress-update `thinking` block — empty with the default `display`. Read content blocks by `type`, return thinking blocks unchanged; to display it, set `display: "updates"` (beta `thinking-display-updates-2026-08-18`) or `"summarized"`; with `between_tools` the text arrives anyway.
- No assistant prefill (400) — use Structured Outputs or instructions in the prompt; `output_format` is deprecated → `output_config.format`.
- Computer use on the Claude API and Google Cloud only via `computer_toolset_20260801` (`computer_20251124` → 400; still allowed on Bedrock); `computer_20250124` nowhere.
- Model IDs: `claude-sonnet-5-5` (Claude API, Google Cloud, Microsoft Foundry, Claude Platform on AWS), Amazon Bedrock `anthropic.claude-sonnet-5-5`. Reliable knowledge cutoff Jun 2026.

## Migration notes
- **MIGRATING TO Sonnet 5.5 (from Sonnet 5)** — the six points in the docs: (1) `thinking: disabled` → `between_tools` at effort `high` or below; (2) `tool_choice` `any`/`tool` → `auto` plus strict tool use; (3) keep the conversation append-only, make instruction/tool changes via mid-conversation system message instead of editing; (4) `computer_20251124` on Claude API/Google Cloud → toolset; (5) advisor tool: do not use Opus 4.8, 4.7, 4.6, Sonnet 5, Sonnet 4.6 or Haiku 5.5 as the advisor (400); (6) read text between tool calls from thinking blocks (set `display`). Also re-run the effort sweep and add refusal handling.
- **MIGRATING TO Sonnet 5.5 (from Sonnet 4.6 or older)**: additionally expect requests without a `thinking` field to think now (check `max_tokens`); replace `budget_tokens` with effort (no fixed conversion; evaluate two or three levels); remove sampling parameters; set `display: "summarized"` if thinking is shown; recount tokens (~30% more) and adjust image token budgets; `xhigh` is new.
- **From Sonnet 4.5 or older / Haiku 4.5**: additionally replace prefills, read tool input with a JSON parser, set effort explicitly, remove the context-window beta header and `interleaved-thinking-2025-05-14`, replace `fine-grained-tool-streaming-2025-05-14` with `eager_input_streaming: true` per tool; from Haiku 4.5, re-baseline costs (higher price; cache minimum drops from 4,096 to 512).
- **AWAY FROM Sonnet 5.5**: `between_tools` is accepted only by Sonnet 5.5 — switch to the disabling mechanism of the target guide (Sonnet 5: `disabled`). Forced tool use works again elsewhere with adaptive thinking (not with manual extended thinking), except on Opus 5.5, Fable 5.1 and Mythos 5.1. Apart from Opus 5.5, no model reads Sonnet 5.5 thinking blocks → reasoning continuity is lost on switching. Per-message effort and mid-conversation system messages are missing on Sonnet 5 (there, top-level `system`). Keep the instructions against reasoning in response text if the target also knows `reasoning_extraction`.
- Lifecycle: status *Active (latest)*, release 28 Sep 2026, retirement not before 28 Sep 2027 (Anthropic platforms; Bedrock/Google Cloud set their own dates).
