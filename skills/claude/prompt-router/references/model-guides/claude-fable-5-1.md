# Claude Fable 5.1

## Reasoning / Thinking
- Type: **adaptive, always on**. Omit `thinking` or send `{type: "adaptive"}`; `{type: "disabled"}` and `{type: "enabled", budget_tokens: N}` both return 400 — `disabled` at **every** effort level (Opus 5 still accepts it up to `high`).
- Depth is controlled solely via `output_config.effort` (`low | medium | high | xhigh | max`), default `high`. Interleaved thinking runs automatically, without a beta header.
- `thinking.display` defaults to `"omitted"` (empty thinking blocks); `"summarized"` returns a summary; the raw chain of thought is never returned. New: `display: "updates"` (beta `thinking-display-updates-2026-08-18`) returns the progress notes between tool calls readably in the progress `thinking` blocks (no `text` block; each non-empty `thinking` block is then a status line), while the reasoning stays hidden.
- **Per-message effort** (beta `mid-conversation-output-config-2026-07-01`): a `role: "system"` message with empty `content` and `output_config.effort` raises or lowers effort mid-conversation, **without** invalidating the prompt cache. Takes effect from the next user turn.
- **Thinking blocks are bound to the model that generated them** and only transfer in one direction: Fable 5.1 reads blocks from Opus 5, Fable 5, Mythos 5 and older models and, on the Claude API, from Opus 5.5 (but not those from Sonnet 5.5); blocks from Fable 5.1 are only readable by Fable 5.1 and Mythos 5.1. Unreadable blocks are discarded server-side, do not count toward `input_tokens` and are not billed — reported as `input_transformations` with `thinking-binding-controls-2026-08-01`, otherwise silently.
- **Editing earlier turns invalidates all later thinking blocks** → 400 with `The block is bound to a different conversation`. Enforced for accounts created from 31 Aug 2026; older accounts only when `thinking.block_binding.prefix_mismatch_behavior` is set (`"error"` | `"drop_block"`). Triggers: rewriting/removing turns, per-request injected reminders that are later deleted, rebuilding `system` or `tools`, changing bytes behind an image/document URL. Harmless: trimming leading thinking blocks from the front, server-side compaction/context editing, moving `cache_control`, changing `effort`.
- Non-default values for `temperature`/`top_p`/`top_k` → 400.

## Prompting style
- Anthropic explicitly says that existing **Fable 5 prompts work well unchanged** — there is no requirement to rewrite; there are only a handful of behavioral deltas, against which individual lines can be added.
- **Rerun the effort sweep**: start at `high`, test all levels against your own evals. Level names do not correspond to the same amount of thinking across models; `medium` is roughly Fable 5-level at lower cost.
- **Keep the conversation append-only**: send reminders as turn-scoped system messages (`clear_at: "next_user_message"`, beta `mid-conversation-system-clear-at-2026-08-21`) and leave old copies byte-for-byte intact; change `system`/`tools` via a mid-conversation system message or `tool_addition`/`tool_removal` instead of rebuilding them.
- **Tool-batching nudge** in implicit agent loops, placed after the `tool_result` blocks: "First privately list what you need next; then request every item that doesn't depend on another's result in this one response."
- **Grant autonomy explicitly**, otherwise the turn ends with "Next, I'll…" or "Shall I…?". The most effective sentence according to the docs: tell the model that no one is watching in real time and that clarifying questions block the work; add the rule to check the final paragraph before the end of the turn for unfulfilled commitments.
- **Remove old anti-formatting rules** — they were written against older, over-formatting models and suppress structure that is needed here. Likewise remove "hold all findings for the final response" lines and instead explicitly request updates (opening line, interim status, closing recap).
- Against unmarked adoption from sources: **one complete example** (user request + correct answer + rationale) in the system prompt, not just a rule.
- Add a scope rule against unrequested fixes and test sprawl, plus a targeted-edit rule against whole-file rewrites; for client-side compaction, explicitly list what the summary must retain.
- Run vision work as an agent with a crop/zoom tool (or a container with PIL/OpenCV); start sub-agents asynchronously and let the lead agent keep working.
- **Do not request reasoning in the response text**: prompts, skills and tool descriptions that have the model write out its thinking/reasoning — verbatim or in a fixed format (a `<thinking>`, `<reasoning>` or scratchpad section before the answer, a `reasoning`/`thinking`/`trace` field in JSON output or tool input, a reasoning log, reasoning "verbatim"/"in full") — can be refused with `stop_reason: "refusal"` and `stop_details.category: "reasoning_extraction"`. Instead, request a short justification, the evidence, or a summary of the steps taken; if the reasoning itself is needed, keep thinking on and read the thinking blocks with `display: "summarized"`. This category has no fallback model (change the prompt rather than resending), and a refusal before any output is billed.

## Strengths & weaknesses (prompt-relevant)
- Strengths (gains over Fable 5, largest at high effort): agentic coding over multi-hour sessions (multi-file features, large refactors/migrations, debugging, code review); knowledge work with documents, spreadsheets and slides from question to finished artifact; multi-step web research; vision on dense charts, filings and nested tables in PDFs; long-context linking across the full 1M window; computer use including recovery after failed steps. Multilingual performance at Fable 5 level.
- At `low`, the docs say it is often competitive with Opus and Sonnet models on cost per task while scoring better — measure this before any downgrade to a smaller model.
- Weaknesses/quirks: **fewer parallel tool calls** when the next independent reads are only implied (coding harnesses, computer use) — costs turns, not quality; **fewer visible progress texts** in long tool chains, more so at high effort; at `low`, less frequent search/retrieval calls (answers from memory more often); **denser prose** (longer sentences, fewer paragraphs); **less formatting** (bold, headers, lists); **unmarked quotes** in summaries; **whole-file rewrites** instead of surgical edits.
- At `xhigh`/`max`, the model sometimes drafts long deliverables in its thinking first and then writes them out again → doubled length, `max_tokens` risk. Docs recommendation: run such requests at `high`, size `max_tokens` generously, and append a note that reasoning and response share **one** limit.
- Safety classifiers return `stop_reason: "refusal"` (fewer false positives than Fable 5 at launch; vulnerability searching in source code is allowed). Trigger patterns: compile-check phrasing ("Does this program compile without errors?" → better "Are there any bugs in this program?"), less common programming languages (include language docs), base64 in tool outputs (remove).

## Output & format conventions
- 1M context window as default **and** maximum at standard price across the whole window, 128k output tokens. Minimum cacheable prefix: 512 tokens.
- **Forced tool use is removed**: `tool_choice: {"type": "any"}` and `{"type": "tool", "name": ...}` return 400 `invalid_request_error` with `tool_choice: type "tool" and "any" are not supported for this model.` — the same check applies on the token-counting endpoint. `auto` (default) and `none` unchanged. Replacement: `auto` plus an explicit instruction on when the tool applies, together with `strict: true` or structured outputs.
- No assistant prefill (400).
- Prices per MTok: input $10, output $50, 5m cache write $12.50, 1h cache write $20, **cache read $0.25** — 0.025× input (Opus 5.5/Sonnet 5.5: 0.05×, other Claude models 0.1×); batch $5/$25. Because cache reads are so cheap, it pays to push the compaction point later.
- Tokenizer same as Fable 5 (introduced with Opus 4.7): roughly 30% more tokens for the same text compared with models before Opus 4.7.
- Model IDs: Claude API, Google Cloud, Microsoft Foundry and Claude Platform on AWS `claude-fable-5-1`; Amazon Bedrock `anthropic.claude-fable-5-1`. Status *Active (latest)*, release 1 Sep 2026, retirement not before 1 Sep 2027. Reliable knowledge cutoff Jun 2026.
- `stop_reason: "refusal"` arrives as HTTP 200 with `stop_details` — check before reading `content`. Permitted fallback targets are Claude Opus 4.8 and Claude Opus 5; `fallbacks: "default"` (beta, header `server-side-fallback-2026-07-01`, Claude API only) routes by category, and fallback credit refunds the prompt-cache cost of the model switch. Refusals before any output have been billed since 24 Sep 2026 when `stop_details.category` is `bio`, `frontier_llm` or `reasoning_extraction` (not before); in other categories still not billed. Mid-stream refusals bill input plus output already streamed.
- **30-day retention mandatory**, no ZDR without explicit authorization from Anthropic; covered model.
- Content provenance: text outputs carry Anthropic's statistical watermark on all platforms (no extra tokens, no hidden characters); image/video/audio files retrieved via the Files API carry signed C2PA content credentials.

## Migration notes
- **AWAY FROM Fable 5.1**: thinking blocks are unreadable for every other model except Mythos 5.1 (including Opus 5.5) and are discarded — reasoning continuity is lost on switching; replace with a summary where needed. Forced tool use (`tool_choice: any`/`tool`) is allowed again on Fable 5, Opus 5 and Opus 4.8; on Opus 5.5 and Sonnet 5.5 still 400 (Haiku 5.5: unverified); `thinking: {type: "disabled"}` is possible again on Opus 5 and Haiku 5.5 up to effort `high`, 400 on Opus 5.5 at every level, 400 on Sonnet 5.5 (use `between_tools` instead, up to `high` only); the append-only requirement only drops for targets without a prefix check — Opus 5.5 and Sonnet 5.5 also enforce it for accounts from 31 Aug 2026 (the cache argument remains). Remove beta specifics: `display: "updates"`, turn-scoped system messages, `prefix_mismatch_behavior`. Per-message effort (`mid-conversation-output-config-2026-07-01`) by contrast keep when the target is Opus 5.5, Opus 5, Sonnet 5.5, Haiku 5.5 (each Claude API/Google Cloud; on Bedrock only Opus 5.5) or Mythos 5.1; on Fable 5 it returns 400. Critically review the Fable 5.1 compensations — the batching nudge, the autonomy block, the anti-mannered-prose instruction, the "more formatting" rule, the targeted-edit rule and the citation example — against models that already over-format or over-cite; these will backfire. The 0.025× cache-read sentence drops out (Opus 5.5/Sonnet 5.5: 0.05×, other models 0.1×). ZDR suitability depends on the target: Opus 5 and Opus 4.8 are available under ZDR, Fable 5 still requires 30-day retention (otherwise 400).
- **MIGRATING TO Fable 5.1 (from Fable 5)**: swap the model ID, remove forced `tool_choice` values, return thinking blocks unchanged (including empty ones), make history append-only and run the three-step check with `thinking-binding-controls-2026-08-01` + `prefix_mismatch_behavior: "drop_block"` and log `input_transformations`, rerun the effort sweep from `high`, check agent loops for one-call-per-turn and add the batching nudge, and set `display: "updates"` for UI narration.
- **MIGRATING TO Fable 5.1 (from Opus 5)**: additionally remove every `thinking: {type: "disabled"}` (here 400 at every effort level) and re-size `max_tokens` for routes that previously ran without thinking; text between tool calls no longer comes as a `text` block but as a progress `thinking` block; the safety categories are broader than Opus 5's (including `bio`, among others; `reasoning_extraction` applies on both models); price doubles to $10/$50; clarify ZDR suitability in advance.
- **MIGRATING TO Fable 5.1 (from Opus 4.8 or older)**: first work through the Fable 5 migration path (adaptive thinking, remove `budget_tokens`/sampling parameters/prefill, effort, 512-token cache minimum, refusal handling), then the Fable 5 delta. Integrations from that era truncate old turns, rebuild `system` per request or compress client-side — exactly the patterns that later invalidate all thinking blocks here.
