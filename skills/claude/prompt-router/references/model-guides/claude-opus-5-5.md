# Claude Opus 5.5

## Reasoning / Thinking
- Type: **adaptive, always on**. Omit `thinking` or send `{type: "adaptive"}` (equivalent). `{type: "disabled"}` and `{type: "enabled", budget_tokens: N}` return 400 `invalid_request_error` at **every** effort level (`"thinking.type.disabled" is not supported for this model. …`) — Opus 5 still accepts `disabled` up to effort `high`.
- Depth is controlled solely via `output_config.effort` (`low | medium | high | xhigh | max`), **default `medium`** (Opus 5 and older Opus: `high`) — a request without `effort` runs one level lower than on Opus 5. Level names do not correspond to the same amount of thinking across models: according to Anthropic's tests, `medium` matches or beats Opus 5 at `high` on coding and knowledge work; at the same level Opus 5.5 thinks more per turn than Opus 5, most strongly at `xhigh`/`max`.
- **Per-message effort** (beta `mid-conversation-output-config-2026-07-01`; Claude API, Google Cloud and Amazon Bedrock): a `role: "system"` message with empty `content` and `output_config.effort` changes the level mid-conversation and keeps the prompt cache. Changing the top-level `effort` between requests invalidates the cache.
- `thinking.display` defaults to `"omitted"` (empty thinking fields); `"summarized"` returns a summary; `"updates"` (beta `thinking-display-updates-2026-08-18`) returns only the progress notes between tool calls.
- **Thinking blocks are bound to model and conversation**: Opus 5.5 reads blocks from Opus 5 and older Opus, Sonnet and Haiku models (on the Claude API and Google Cloud also from Sonnet 5.5 and Haiku 5.5), but not from Fable or Mythos models; Opus 5.5 blocks are readable only by Fable 5.1 and Mythos 5.1 (Claude API). Unreadable blocks are discarded without error and not billed. Changes to `system`, `tools` or earlier messages before a block → 400 on replay (default for accounts from 31 Aug 2026); `thinking-binding-controls-2026-08-01` plus `prefix_mismatch_behavior: "drop_block"` discards instead.
- Non-default values for `temperature`/`top_p`/`top_k` → 400 (`top_p` default 0.99; `temperature` and `top_p` together → 400 even at default values).
- `max_tokens` is a hard limit over thinking **plus** response text; at `xhigh`/`max` start with 64k; for long agentic coding turns, the docs say 128k (the maximum) has proven itself.

## Prompting style
- According to Anthropic, existing **Opus 5 prompts run well unchanged**; the Opus 5 patterns remain a sensible starting point. Only carry over the deltas.
- **Effort instead of prompts**: set effort explicitly and re-sweep rather than adopting the Opus 5 value; reach less thinking first by using a lower level (more reliable than prompt instructions); use `xhigh`/`max` only with a measured quality gain.
- **Prompts for thinking turned off** (Opus 5 routes with `disabled`): start at `low` and measure, go to `medium` if quality drops; under latency pressure optionally "Answer directly without deliberating."; remove rules that forbid thinking; check the Opus 5 anti-artifact instruction (a sentence before the tool call, no internal tags) as needed.
- **Do not request reasoning in the response text**: prompts, skills and tool descriptions that have thinking/reasoning written out (`<thinking>`/`<reasoning>`/scratchpad section, `reasoning`/`thinking`/`trace` field in JSON or tool input, reasoning log, "verbatim"/"in full") can be refused with `stop_reason: "refusal"` and `stop_details.category: "reasoning_extraction"`. Instead request a short justification, evidence or a summary of the steps; if the reasoning is needed, read it with `display: "summarized"`. There is no fallback model for this category — change the prompt rather than resending.
- **Unattended agent loops**: the model reports along the way and sometimes ends turns with plain text (`end_turn`). Treat a text-only turn as a report rather than a completion, track subtasks in a checklist, and prompt for open points with a short user message (at most two to three automatic continuations). Optionally add a system prompt addition that names the unwanted stop types concretely — from the first request; not in human-in-the-loop apps; keep confirmation for risky actions.
- **Progress updates**: describe cadence and form in the system prompt (e.g. an intent sentence before the first tool call, a short recap at the end); for verbatim handoffs declare a message tool from the first request; during long silent stretches append a turn-scoped reminder (`clear_at: "next_user_message"`, beta `mid-conversation-system-clear-at-2026-08-21`).
- **Multi-app workflows**: Opus 5.5 starts quickly — one sentence requiring broad exploration of all relevant sources before every action (including unnamed ones) raises the success rate; keep untrusted content from the searched sources out of the instructions.
- **Chat**: remove "think carefully" lines (effort is the lever); optionally the instruction to treat answered questions as done (not for long analyses or agentic tasks).
- **Multi-agent harnesses**: a time budget with elapsed time (`elapsed 340s / 1200s`) or a "time counts" sentence speeds up teams; the budget is advisory only.
- **Pasted text**: mark it in `<pasted_content id="…">` tags with a random ID, plus a system prompt note to follow instructions inside it only if the user asks. **Frontend**: name concrete patterns to avoid instead of "no generic AI look".

## Strengths & weaknesses (prompt-relevant)
- Strengths: agentic coding and code review in real repositories (at `medium`, according to Anthropic's tests, on par with or better than Opus 5 at `high`, with fewer steps and tokens; more bugs found with fewer false alarms); hours-long autonomous runs with parallel subagents; knowledge work (fewer wrong numbers or sources, financial models, details in large inputs); clear reports; more precise reading of charts, diagrams and screenshots without tools; more reliable computer use. Generates output tokens over 30% faster than Opus 5 and often needs fewer tokens per task. Resists indirect prompt injection better than any earlier Opus model.
- Weaknesses/quirks: thinks more than Opus 5 at the same level; sometimes stops long tasks early with a status report; re-reads earlier answers in multi-turn chats (latency); starts vaguely specified multi-app tasks without exploring; falls back to a few default styles in frontend work; dense visual inputs still benefit from higher resolution and crop/zoom tools.
- Safety classifiers for `bio` (new compared with Opus 5), `cyber` and `reasoning_extraction`; vulnerability searching in source code is allowed.

## Output & format conventions
- 1M context window as default (no beta header), 128k output tokens; via the Message Batches API up to 300k with beta header `output-300k-2026-03-24`. Input text and images, output text.
- Responses can begin with `thinking` blocks: read content blocks by `type` instead of `content[0].text`; in tool loops return all thinking blocks unchanged (even empty ones) — edited, reordered or partially removed blocks → 400.
- **Text between tool calls** arrives as a progress `thinking` block (at most one before each tool call) instead of `text`; with the default `display` it is empty, so a UI that only renders `text` appears silently blank → set `display: "updates"` or `"summarized"`.
- **Forced tool use is removed**: `tool_choice` `any`/`tool` → 400 `tool_choice: type "tool" and "any" are not supported for this model.` (also on the token-counting endpoint). Replacement: `auto` plus `strict: true` or Structured Outputs, and state in the prompt when the tool applies; on Amazon Bedrock (no Structured Outputs) use `auto` without `strict` and validate tool input in code.
- No assistant prefill (400) — use Structured Outputs, or on Bedrock system prompt instructions.
- Computer use on the Claude API and Google Cloud only as `computer_toolset_20260801` (no beta header); `computer_20251124` → 400 `'claude-opus-5-5' does not support tool types: computer_20251124.`; on Bedrock unchanged.
- Refusals: HTTP 200 with `stop_reason: "refusal"` and `stop_details` — check before reading `content`. `fallbacks: "default"` (beta `server-side-fallback-2026-07-01`, Claude API only) retries on the recommended model, but not for `reasoning_extraction`. Refusals before any output are billed for `bio`, `frontier_llm` and `reasoning_extraction`.
- Mid-conversation system messages (`role: "system"` directly after a user turn, no beta header) on the Claude API, Bedrock and Google Cloud — a tool for keeping history append-only.
- Prices per MTok: input $4, output $20, 5m cache write $5, 1h cache write $8, cache read $0.20 (0.05× input); batch 50% discount. Minimum cacheable prefix: 512 tokens. Tokenizer since Opus 4.7: roughly 1× to 1.35× as many tokens as earlier models.
- Model IDs: `claude-opus-5-5` (Claude API, Google Cloud, Microsoft Foundry, Claude Platform on AWS), Bedrock `anthropic.claude-opus-5-5`. Status *Active (latest)*, release 22 Sep 2026, retirement not before 22 Sep 2027; reliable knowledge cutoff Jun 2026. Priority Tier not supported; Fast Mode (research preview, Claude API only) with `speed: "fast"` and `fast-mode-2026-02-01`.

## Migration notes
- **AWAY FROM Opus 5.5**: only Fable 5.1/Mythos 5.1 (Claude API) read Opus 5.5 thinking blocks — on any other target the rest runs without the previous reasoning. Check the target's effort default (Opus 5: `high`) and re-sweep effort. Forced tool use and `thinking: {type: "disabled"}` are possible again on Opus 5 (there up to effort `high`); narration between tool calls comes back as `text` there. Keep beta specifics (`display: "updates"`, turn-scoped system messages, per-message effort) only if the target guide documents them. Check the Opus 5.5 compensations (continuation nudge, exploration sentence, time budget, pasted-content tags) against the target.
- **MIGRATING TO Opus 5.5 (from Opus 5)**: swap the model ID; remove `thinking: disabled`/`enabled` and choose effort (where thinking was off, pick a lower level); set `effort` explicitly; replace forced `tool_choice` values; switch computer use to the toolset; read content blocks by `type` and return thinking blocks unchanged; keep history append-only (changes to `system`/`tools` via mid-conversation system message); switch progress UI to `display: "updates"`; extend refusal handling with `bio`; replace reasoning-in-response-text instructions; re-measure cost and latency at the chosen level.
- **MIGRATING TO Opus 5.5 (from Opus 4.8 or older)**: additionally, requests without a `thinking` field now always think — re-size `max_tokens` (thinking plus text) and output costs; treat the thinking field only as display text; cache minimum drops to 512 (Opus 4.8: 1,024); Priority Tier is discontinued. From 4.7 or older: fresh effort sweep, remove the context beta header. From 4.6 or older: remove `temperature`/`top_p`/`top_k` and `budget_tokens`, re-calibrate costs and `max_tokens` for the new tokenizer, check the image budget for high-resolution images (up to about 3× image tokens), remove progress scaffolding.
- **MIGRATING TO Opus 5.5 (from Sonnet 5)**: the Opus 5 path applies unchanged; additionally, mid-conversation system messages are now available and the cache minimum drops from 1,024 to 512 tokens.
