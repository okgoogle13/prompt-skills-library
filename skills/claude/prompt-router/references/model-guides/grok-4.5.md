# Grok 4.5

## Reasoning / Thinking
- Type: **cannot be switched off**. The reasoning page says explicitly "Reasoning cannot be disabled" — there is no `none` path as on grok-4.3.
- Documented ladder (reasoning page, release notes): `reasoning.effort` or `reasoning_effort` = `low | medium | high`, **default `high`** ("If not specified, `reasoning_effort` defaults to `high`."). Whoever leaves the parameter unset permanently runs the most expensive documented level.
- **`xhigh`: documented contradictorily.** The reasoning page names grok-4.5 verbatim as a model where `xhigh` is silently treated as `high` ("On models that do not support it, such as `grok-4.5`, requests with `xhigh` are treated as `high`."), while the model page now lists `xhigh` as supported. Effective behaviour is unverified; do not plan on `xhigh` as an extra depth level on 4.5 — a silent downgrade would happen without error or warning.
- **No reasoning summaries.** xAI exposes summaries of the internal reasoning path only for grok-4.7. For grok-4.5 only encrypted reasoning content exists, via `include: ["reasoning.encrypted_content"]`, which can be passed back unchanged in follow-up requests — none of it is readable by humans or a downstream parser.
- Reasoning tokens are billed ("the reasoning tokens are billed as part of your total consumption").
- `presencePenalty`, `frequencyPenalty` and `stop` are blocked for reasoning models: "Requests that include them return an error." Format control must therefore not run through stop sequences.

## Prompting Style
- Positioning per the model page: "SpaceXSI's intelligent coding model for agentic software, engineering, and workflow tasks." Prompt accordingly **agentically and task-oriented** — coding, tool and workflow work, not a general-purpose chat profile.
- The announcement stresses that 4.5 builds end-to-end applications "from single prompts with minimal specification": the task description may stay brief, but **acceptance criteria, target stack and stop conditions still belong in the prompt** — otherwise the model decides them itself.
- Selection logic belongs in the **tool definitions**, not in prose: "What the tool does — helps the model decide when to use it." Parallel tool calling is active by default (`parallel_tool_calls: false` turns it off); `tool_choice` accepts `auto` (default) / `required` / `none` / a forced function. A `parameters` root that is neither an object nor an object union is rejected with `400`.
- Enforce format via **Structured Outputs** (`response_format.type: "json_schema"`): "the response is guaranteed to match your schema." Plan for the limits — string constraints up to 2,048 characters, arrays up to 256 entries, max. 64 object properties; `not` and `if`/`then`/`else` apply only on a best-effort basis.
- Prompt caching runs automatically from the start of the `messages` array. Keep the static part (system prompt, tool definitions) **at the front and unchanged**, and send `x-grok-conv-id` (Chat Completions/gRPC) or `prompt_cache_key` (Responses API) so that requests of one conversation route to the same server — cache entries are per server.
- xAI publishes no model-specific prompting guidance for grok-4.5 (a dedicated developer page now exists only for grok-4.7; `/developers/grok-4-5` redirects there). Any further style claim is unverified.

## Strengths & Weaknesses (prompt-relevant)
- Strengths: pronounced **coding/agent profile** (Rust and C/C++ are named explicitly in the announcement); high **token efficiency** — per the announcement roughly 4.2x fewer output tokens than Opus 4.8 (max) on software-engineering tasks and "twice greater token efficiency" versus comparable models, at about 80 TPS; office artefacts (multi-sheet Excel models with formulas and web research, PowerPoint charts, Word prose); full flagship throughput ceiling (150 rps / 50M tpm, identical to grok-4.6/4.7); the cheapest cached input in the 4.5/4.6/4.7 class ($0.30 instead of $0.50 under 200k); function calling and structured outputs both yes.
- Vendor-cited benchmarks (not independently verified): DeepSWE 1.0 62.0%, SWE Bench Pro 64.7%, Terminal Bench 2.1 83.3%, SWE Marathon 29.0%.
- Weaknesses/quirks: **`xhigh` documented contradictorily** and **no switchable-off reasoning** — the documented effort range is narrower than its neighbours'; no readable reasoning summaries; **Batch API "Not supported"** (grok-4.3 gives a 20% discount there); according to the model page only regions us-east-1 and us-west-2, **no EU region** (the release notes report only availability "in the API console for EU users" in July); **price cliff at 200k prompt tokens** — from there the doubled rate applies to ALL tokens of the request; **no published knowledge cutoff** and no published output limit; the model overview explicitly recommends grok-4.7 for code and chat, not 4.5.

## Output & Format Conventions
- 500,000-token context window; input text + image, output text only. Max. output tokens: not published (unverified). Knowledge cutoff: not published (unverified) — the overview lists only the cutoff of grok-4.7 (May 2026).
- Function calling: yes; structured outputs: yes; reasoning: yes; Batch API: "Not supported".
- Prices per 1M tokens: input $2.00 (<200k prompt) / $4.00 (≥200k), cached input $0.30 / $0.60, output $6.00 / $12.00. Rate limits: 150 requests/s, 50M tokens/min; regions us-east-1, us-west-2.
- Aliases documented on the model page: `grok-4.5-latest` **and** `grok-build-latest`. `grok-build-latest` names no generation, so it is a rolling pointer — per the developer page the default model of Grok Build is now grok-4.7; do not use it as a stable pin to 4.5.
- Release on 16 July 2026 per the official announcement (the only reliable date source). The release notes page lists the entry only under the month heading "July" **without a year**, so it is not usable as a date source.

## Migration Notes
- **AWAY FROM grok-4.5** (to grok-4.7, which xAI recommends for code and chat, or to grok-4.6): per the reasoning page `xhigh` is then actually executed rather than silently folded to `high` — measure cost and latency before adopting the value; cached input rises from $0.30 to $0.50 (<200k), standard input/output stay identical. Context (500k), rate limits and missing batch support stay the same; regions gain us-central-1 and the US regional endpoint `https://us.api.x.ai/v1` (+10%), but there is still no EU region. Only grok-4.7 documents reasoning summaries, and on the Responses API `reasoning.encrypted_content` comes back with every answer there — send reasoning items back unchanged in the next `input`. If moving to grok-4.3 instead: plan for `reasoning_effort: none` as the zero-thinking path (default there is `low`), use the 1M context and the EU region, plan for the batch discount — the reasoning class rules are not documented for 4.3, however.
- **TO grok-4.5**: (1) Remove every `xhigh` value or set `high` deliberately — per the reasoning page it is silently downgraded, and the prompt assumption of "deepest reasoning" no longer holds. (2) Set `reasoning_effort` explicitly rather than trusting the default: unset means `high`. (3) Lift all zero-thinking fast paths (grok-4.3 `none`, Claude `thinking: disabled`, OpenAI `minimal`) to `low` — reasoning cannot be switched off, so the latency and cost budgets of those routes must be recalculated. (4) Remove `presence_penalty`, `frequency_penalty` and `stop` from requests (otherwise an error) and move format control entirely to Structured Outputs. (5) Stabilise the prompt prefix and add `x-grok-conv-id` or `prompt_cache_key`, otherwise the cache benefit is not realised. (6) Re-plan batch jobs — the Batch API does not serve this model. (7) Chunk before exhausting context: from 200k prompt tokens the rate doubles for input **and** output of the whole request. (8) Rebuild prompts or pipelines that evaluate a visible reasoning trace — only encrypted reasoning is available here. (9) EU data residency is not possible (only us-east-1/us-west-2). (10) Check tool definitions: parallel tool calling is on by default; where strict ordering is needed, set `parallel_tool_calls: false`.
