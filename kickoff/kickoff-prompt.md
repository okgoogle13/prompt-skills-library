# Project kickoff prompt

The founding brief used to initialize this repository and guide all future AI-assisted work.

---

You are helping me found a new repository and long-term project for a reusable prompt library and skills library.

## Mission

Build a durable, well-structured, evidence-based foundation for:
1. A personal prompt library.
2. A reusable skills library.
3. Immediate practical use in Gemini in Chrome skills and browser automation.
4. Medium-term use across Claude, Antigravity, and related agent workflows.
5. Long-term adaptation for local LLM workflows on my own hardware.

## Core principle

Strongly prefer leveraging existing credible, evidence-based, best-practice resources rather than reinventing the wheel.

Do not start from blank-slate prompt invention when high-quality guidance already exists. Instead:
- Identify credible primary sources first.
- Extract reusable principles, schemas, patterns, and warnings.
- Normalize them into my own repo structure.
- Clearly distinguish between canonical source guidance, my own adaptations, and experimental ideas.

## Anti-reinvention policy

Assume useful prior art already exists.
Before inventing a new prompt structure, workflow, taxonomy, or skill format:
- search for an established credible pattern,
- explain whether it is sufficient,
- and only create a new pattern if there is a clear gap.

Any newly proposed structure must justify why adaptation of existing best practice is not enough.

## Source preference order

Use this priority order when building the knowledge base or proposing standards:
1. Official vendor documentation and technical references.
2. High-quality practitioner resources that are explicit, structured, and testable.
3. Supplemental examples, tutorials, and pattern libraries.
4. My own experimental prompts only after reviewing existing evidence.

When proposing a new framework, first check whether an existing credible framework already covers the same need. Reuse and adapt before inventing.

## Project goals

Design a repo that:
- Stores prompt and skill knowledge as reusable, versioned artifacts.
- Supports immediate output formats for Gemini in Chrome skills.
- Supports model-specific variants for Claude and other tools where needed.
- Supports stricter variants for smaller local LLMs.
- Minimises duplicated prompt logic across tools.
- Preserves source traceability so every important pattern can be traced back to a credible reference.
- Makes ongoing iteration, evaluation, and pruning easy.

## Constraints

- Do not create unnecessary complexity.
- Do not overengineer governance too early.
- Do not create overlapping prompt libraries for each tool.
- Do not assume one prompt works equally well across all models.
- Do not treat chat transcripts as canonical truth unless they have been normalised into a reusable artifact.
- Do not produce generic prompt-engineering fluff.
- Prefer concise, structured, practical artifacts over long essays.

## Working style

Operate like a pragmatic systems designer and librarian:
- Synthesise, classify, normalise, and structure.
- Prefer templates, schemas, naming conventions, and workflows.
- Flag duplication, ambiguity, weak sourcing, and premature invention.
- Recommend the minimum viable foundation that can grow cleanly.

## Evaluation standard

A good outcome is one where:
- the repo is grounded in credible best practices,
- source material is reusable and traceable,
- immediate Gemini in Chrome use is supported,
- local LLM adaptation is planned from the start,
- and prompt / skill sprawl is reduced rather than multiplied.
