# Prompt Router Redesign Specification: Lean Modular Architecture

## 1. Problem Statement
**How might we** cut `/prompt-router`’s per-use token footprint by ~70% for a heavy daily `write`/`optimise` workflow—sizing every response to the task and actively challenging bloated context—while preserving all five safety and fidelity safeguards?
- **Baseline evidence:** `1.3M` tokens across `96` uses (`~13.5k` tokens/use) `[measured]`. Static always-read files consume **`536` lines / `~13,042` tokens `[estimated @ ~4 chars/token]`** before any model guide or user attachment is opened: [SKILL.md](file:///Users/okgoogle13/.claude/skills/prompt-router/SKILL.md) (`187`L, `~5,528` tokens `[measured / estimated]`), [references/patterns.md](file:///Users/okgoogle13/.claude/skills/prompt-router/references/patterns.md) (`254`L, `~4,339` tokens `[measured / estimated]`), and [references/model-registry.md](file:///Users/okgoogle13/.claude/skills/prompt-router/references/model-registry.md) (`95`L / `89` models, `~3,175` tokens `[measured / estimated]`).

## 2. Recommended Direction
Adopt **Direction A (Hot/Cold Route Split)** combining variations V2 + V3 + V4 + V5 + V6 + V7:
1. **Lean Dispatcher ([SKILL.md](file:///Users/okgoogle13/.claude/skills/prompt-router/SKILL.md), ~78 lines):** Holds intake, the authoritative 5 safeguards, folded 1-line `clarify`, host-only `write` drafting rule, optional 2-line `Profile`-based model recommendation, 3-tier proportional output contract, 3-line Context Audit trigger, on-demand platform-profile hooks (`codex-cli-chatgpt-go.md`, `perplexity-pro.md`, `google-ai-pro-antigravity.md`), 3-line `adapt` pointer, and a 5-line pre-return verification gate.
2. **`write` + `optimise` Compiler ([references/patterns.md](file:///Users/okgoogle13/.claude/skills/prompt-router/references/patterns.md), ~82 lines):** Loaded **only** on `write` and `optimise`. Embeds the 4 Karpathy rules, concrete literal-token syntax list (`§1`), 3-line Context Audit rubric, Coding-task brief (`§4`), and Claude-target rules (`§5`).
3. **Cold Route Shards (`references/review.md` ~28 lines; `references/adapt.md` ~32 lines):** Lazy-loaded **only** when `review` or `adapt` is invoked; neither route loads `patterns.md`.
4. **Two-Tier Registry ([references/model-registry.md](file:///Users/okgoogle13/.claude/skills/prompt-router/references/model-registry.md) ~26 lines + `references/model-registry-archive.md` ~75 lines):** The active shortlist contains **20 canonical active registry rows** (including `claude-opus-5-5-orchestrator`, now a dedicated canonical row backed by `references/model-guides/claude-opus-5-5-orchestrator.md` per commit `9190f0d`), plus a traceable `Profile` column (8–16 words). No registry row may exist without a corresponding file in `references/model-guides/`. Remaining **69 cold rows** move to the lazy archive, read only on a shortlist miss.

## 5. Route Table & `Profile` Recommendation Rules
| Route | Trigger (from user request only) | Files Loaded (beyond `SKILL.md`) | Behaviour & Host-Only / No-Model Rule |
|---|---|---|---|
| **write** *(Fast path)* | `write`, `create`, `draft`, `build`, rough notes + file paths/status | `patterns.md` + `model-registry.md` (if model named or recommending) + ≤1 target guide | Compiles notes into verifiable prompt. **Host-only/no-model fix:** drafts prompt using host conventions (`@path` for Claude Code, `#file:` for Copilot) with 0 guide reads instead of falling back to `review`. |
| **optimise** *(Second)* | `optimise`, `improve`, `tighten`, `compress`, context/token bloat, or unclear verb + model | `patterns.md` + `model-registry.md` (if model named) + ≤1 target guide | Surgical edits + context compression. Runs with 0 guides on model-agnostic bloat requests. |
| **review** *(Light)* | `review`, `check`, `audit`, `"is this ready?"`, or unclear verb with no model | `references/review.md` + (`model-registry.md` + ≤1 guide if model named) | Findings only (no rewrite): `Verdict: Ready \| Fix first` + ≤5 ranked material findings (`[SEVERITY] Clause/gap → failure mode → smallest fix`). |
| **adapt** *(Pointer)* | `adapt`, `migrate`, `port`, `convert`, `from A to B` | `model-registry.md` (+ `archive.md` on miss) + `references/adapt.md` + ≤2 guides | 3-line pointer in `SKILL.md` delegates `Self-check:`, source-vs-target guide diffing, and `[source unspecified]` handling to `references/adapt.md`. |
| *(Folded)* **clarify** | Empty/`$ARGUMENTS` input, unresolved/ambiguous model ID, or `write` task with ≥2 divergent meanings | `0` guides (`model-registry.md` + `archive.md` only if model lookup ran) | **1-line universal gate in `SKILL.md`:** State what failed/ambiguous, offer ≤5 closest registry IDs if model-related, ask 1 question, stop. |

- **`Profile`-Based Model Recommendation Rules:**
  - Used **only** when no model ID is explicitly named; **a user-named model ID always overrides any recommendation**.
  - Do **not** read a full model guide solely to make a recommendation; use the active registry row in `references/model-registry.md` first (**0 model guides read**).
  - Limited strictly to **maximum two lines**:
    - `Recommended: <model-id> — <1 concise task-oriented reason>`
    - `Alternative: <model-id> — <1 concise trade-off>`
  - **Pre-enablement substantiation gate:** Before enabling `Profile`-based automatic model recommendations, validate every active-row `Profile` against its corresponding `references/model-guides/<model-id>.md` guide or authoritative frontmatter. If a claim cannot be substantiated, set `Profile: unverified` and exclude that model from automatic recommendation until reviewed and evidenced. Never invent, infer, or generalise capabilities beyond what the guide or frontmatter supports.

## 6. Proportional Output-Size Rules
Silent pre-return integrity checks run on **every** turn; printed post-fence blocks are strictly conditional:
| Task Size | Definition | Returned Output Structure | Explicit Block Trigger Rules |
|---|---|---|---|
| **Short** | Single-goal prompt ≤15 lines; 0 assumptions; no bloat; current/verified guide | 1. Fenced prompt<br>2. `Run settings:` *(only if non-default)*<br>3. `Recommended`/`Alternative` *(≤2 lines, only if no model named)* | **Suppress** `Run settings: none needed`, `Assumptions: none`, `What changed and why`, and `Guide status:`. |
| **Medium** | Multi-constraint `write`/`optimise`, coding brief with file paths, or context bloat | Short output **plus** (when non-empty):<br>• `Context audit:` (≤3 lines)<br>• `Assumptions:` (≤3 lines) | • `Context audit:` prints **only** when bloat (>60L notes/logs/dumps), ≥2 file paths, or standing repo rules exist in intake payload.<br>• `Assumptions:` prints **only** when inline `[ASSUMPTION: …]` slots were added. |
| **Complex** | Multi-step architecture/agent prompt, `adapt`, conflicting constraints, or legacy/stale/unverified guide | Medium output **plus**:<br>• `What changed and why:` (≤5 bullets)<br>• `Guide status:` (1–2 lines) | • `What changed and why:` prints **only** on `adapt`, on `optimise` with structural/bloat cuts, or Complex `write`.<br>• `Guide status:` prints **only** on `adapt`, `status: legacy` (naming `successor`), `last_verified > 180` days old, or when `(unverified)` guide claims apply. |

## 7. Concrete Karpathy & Active Context Audit Wording (`patterns.md`)
Embed verbatim in `references/patterns.md` for `write` and `optimise`:
- **1. Assumptions first (`Think Before Coding`):** *"Do not guess silently. Mark material gaps inline as `[ASSUMPTION: …]`. If a `write` brief has ≥2 plausible interpretations yielding materially different prompts, ask 1 question and stop with 0 guide reads."*
- **2. Simplest prompt (`Simplicity First`):** *"Write the minimum instructions that make the success criterion observable. Add no unrequested personas, multi-agent roles, rubric padding, or speculative edge-case branches. If 40 lines can be 12 without losing a constraint or literal token (§1), write 12."*
- **3. Surgical edits (`Surgical Changes` — `optimise`):** *"Touch only clauses that cause a material failure, conflict with the target guide, or duplicate context. Preserve working phrasing and structure; every edit must trace to a user requirement, context cut, or target-guide rule."*
- **4. `step → verify` loops (`Goal-Driven Execution`):** *"For coding, multi-file, or staged tasks, compile notes and status updates into ordered verification loops (`1. [Action on exact file/range] → verify: [concrete command or check]`) ending with a terminating verification command."*
- **5. Active Context Audit (max 3 lines, payload-only):** *"Inspect only material already present in the intake/conversation payload—never read or open workspace source files merely because file paths are mentioned. When payload exceeds ~60 lines of notes/logs/status, mentions ≥2 files, or repeats project rules, emit `Context audit:` (max 3 lines): (1) removable bloat to drop, (2) precise file or line-range scoping (`path#L10-L45`, `@path`, `#file:`) without opening files, (3) standing conventions to move to `CLAUDE.md` or `GEMINI.md`."*

### 9B. Lookup Order, Parked-Archive Rule & Trade-Off Costs
1. **Step 1 (Host/No-Model Check):** If no model or only a host (`Claude Code`, `Antigravity`, `Gemini`, `ChatGPT`, `Codex`) is named, run `write`/`optimise`/`review` with **0 guide reads** (read `model-registry.md` only if emitting a ≤2-line `Profile` recommendation on `write`/`optimise`; user-named model IDs always override recommendations).
2. **Step 2 (Active Shortlist Match):** Strip trailing effort token (`minimal|low|medium|high|xhigh|max`), normalise, and match `Model ID` or `Aliases` in `references/model-registry.md` (with vendor-prefix strip retry `claude-|openai-|google-|meta-`).
3. **Step 3 (Archive Fallback on Miss):** If unresolved in `model-registry.md`, read `references/model-registry-archive.md` once and run the same exact/alias match (preserving bare `spark` disambiguation and family aliases like `qwen` → `qwen3.8-max`).
4. **Step 4 (Fail-Closed Clarify Gate):** If still unresolved or ambiguous, name the failed phrase, offer ≤5 closest registry IDs, ask 1 question, and stop with **0 model guides read**.
- **Parked-Archive Rule:** Active shortlist contains exactly 20 `status: current` canonical rows (remaining 69 in archive); any model flipped to `status: legacy` or demoted moves to `model-registry-archive.md` on regeneration.
- **Trade-off costs:** Shortlist hit (~95% of runs) saves **`~2,400` tokens `[estimated]`**; shortlist miss costs **+1 `read_file` call** and **`~75` extra header tokens `[estimated]`**.
